## 3. 核心挑战维度

**维度定义**：核心玩法所涉及的挑战类型及主次。

**内容说明**

**核心体验**

观察记忆型解谜：在布满物品的房间中发现细微变化，管理不稳定度避免失控

## 4. 操控方式

**维度定义**：输入方式、输入元素和操控构成。

**内容说明**

**操作方式**

WASD → 移动 → 游戏内任意时刻；鼠标 → 环视 → 游戏内任意时刻；E/RMB → 脉冲校准生成异常 → 非结束状态；LMB → 标记异常 → 需对准目标且在范围内；J → 切换Visor HUD → 非结束状态；F → 手电开关 → 游戏内任意时刻；MMB按住 → 缩放 → 游戏内任意时刻；ESC → 暂停菜单 → 游戏进行中

## 5. 行为路径

**维度定义**：玩家在一次核心循环中重复执行的动作顺序。

**内容说明**

**核心玩法**

玩家在3D房间中巡视，用E键脉冲校准生成异常，通过观察找出被改变的物体并用LMB标记收容，达到目标数量后完成关卡

## 6. 游戏路径（关键节点 + 流失风险）

**维度定义**：从启动到结束的流程节点及已披露的风险。

**内容说明**

**游戏流程**

开始：选择难度后进入房间；操作：脉冲生成异常→巡视观察→标记异常→管理不稳定度；结果：达到收容目标进入结算或不稳定度满失败；继续：重试按钮刷新页面重新开始

## 7. 成长路径

**维度定义**：玩家推进和变强的途径。

**内容说明**

**奖励与成长**

每关目标收容10个异常；不稳定度达100失败；难度影响每tick变异数量与是否有扫描提示

## 8. 核心闭环（目标-规则-反馈-激励）

**维度定义**：目标、规则、反馈、激励和下一目标。

**内容说明**

**目标机制**

每关收容10个异常且不稳定度<100

**玩法达成机制**

观察→发现异常→标记→收容成功反馈与计数更新

**反馈机制**

实时HUD更新（收容数/不稳定度）、日志滚动、音效反馈、visor视觉辅助

**驱动力机制**

关卡递进（3关）、难度选择（3级）、不稳定度管理的紧张感

**延续机制**

完成一关后解锁下一关（debug按钮可跳转），更高难度挑战

## 9. 玩法规则

**维度定义**：核心循环、操作、胜负和结算规则。

**内容说明**

**目标、规则与结算数值**

目标：在不稳定度达100前收容10个异常；误标稳定物体增加不稳定度；每tick未收容的异常增加不稳定度；成功收容减少不稳定度

**已验证流程与未覆盖范围**

实机验证：启动、进入关卡、移动、脉冲、visor、手电、无外部请求；未验证：标记闭环（AI操作限制已提交人工）、后续关卡、结算流程

## 11. 关卡配置

**维度定义**：关卡布局、目标、数量、递进和难度参数。

**内容说明**

**内容规模**

3个关卡（Pocket Dimension 14-B、Abandoned Classroom 7-C、The Overgrown Office），每关不同房间布局与物品密度

**场景、关卡与难度设计**

每关固定房间边界与物品布局，异常物体与类型随机选取，难度递进

## 12. 系统设计

**维度定义**：功能系统及界面流程。

**内容说明**

**玩法系统与相互作用**

AnomalySystem管理异常生成/标记/重置；VisionSystem管理visor与脉冲效果；AudioSystem管理音效与音乐；JournalSystem管理目标信息；PlacementValidator管理物品放置

**界面流程与反馈**

主界面（难度选择+说明）→ 游戏HUD（tick/收容计数/不稳定度/日志/扫描提示）→ 暂停菜单（音量/恢复）→ 结算界面（结果+重试）

**存档方式**

localStorage仅存音量设置（rsi_vol_*），无游戏进度存档；刷新后重新开始
