## 5. 行为路径

**维度定义**：玩家在一次核心循环中重复执行的动作顺序。

**内容说明**

**核心玩法**

选择车手与赛道后参加 3 圈单人赛，自动加速，玩家仅控制左右转向、刹车与道具使用，在 6 车中争取名次与最快圈速。

## 6. 游戏路径（关键节点 + 流失风险）

**维度定义**：从启动到结束的流程节点及已披露的风险。

**内容说明**

**游戏流程**

开始：主菜单 → 选择 Single Race → 选择车辆 → 选择赛道 → 点击 START RACE；操作：倒计时后自动加速，通过转向与刹车沿赛道行驶，拾取道具箱并按键使用；结果：完成 3 圈后进入结算界面，显示名次、圈速与得分；继续：可 Race Again 返回同一赛道或 Menu 返回主菜单。

## 9. 玩法规则

**维度定义**：核心循环、操作、胜负和结算规则。

**内容说明**

**目标、规则与结算数值**

目标：在 3 圈比赛中获得尽可能高的名次与最快圈速；成功/失败：完赛即产生名次，未完成可手动退出；计分：源码中 G.Score.compute 根据名次、圈速、碰撞、脱路等统计计算总分，具体阈值未从源码完全展开。

**已验证流程与未覆盖范围**

实机验证：启动、菜单导航、车辆选择、赛道选择、比赛加载、驾驶操控、碰撞/出界反馈、暂停与退出、刷新后菜单恢复、localStorage 保存；源码确认：键位映射、保存结构、物理与道具系统、多人联机代码存在但未启用；未验证：完整完赛结算界面、多人联机、全部车辆/赛道。

## 11. 关卡配置

**维度定义**：关卡布局、目标、数量、递进和难度参数。

**内容说明**

**内容规模**

固定车辆列表（至少包含 Acclaim GT 等）与固定赛道列表（至少包含 Elkhart Lake）；赛道由程序根据种子生成道具箱摆放，圈数固定为 3 圈。

**场景、关卡与难度设计**

已验证赛道 Elkhart Lake 为 1:10 公路赛道，253 m 实际长度、按 1:10 缩放约 2.5 km，3 圈；其余赛道与关卡总数未在实机中逐一核对。

## 12. 系统设计

**维度定义**：功能系统及界面流程。

**内容说明**

**玩法系统与相互作用**

车辆物理系统：四轮悬挂、转向锁止、速度相关转向极限、自动加速、刹车/倒车判定；碰撞系统：车体与护栏/车辆碰撞，撞车触发粒子与重生的；赛道系统：样条曲线道路、检查点、出界计时与 wrong-way 检测；道具系统：赛道上的可拾取箱子，拾取后随机赋予加速/护盾/攻击等效果；AI 系统：5 辆电脑车辆自动沿赛道行驶；音频系统：引擎、打滑、撞车、背景音乐与 UI 音效。

**界面流程与反馈**

主菜单：Single Race / Multiplayer / Toy Box / Tracks / Options；车辆选择：左右切换车辆，显示名称、类型、速度/操控/加速条，NEXT 进入赛道；赛道选择：左右切换赛道，显示长度与圈数，START RACE 进入比赛；比赛 HUD：名次、圈数、计时、最佳圈速、速度、道具、小地图、暂停按钮；暂停菜单：Resume / Restart / Quit；结算界面：成绩、名次、Race Again / Menu。

**存档方式**

保存内容：bestLap、bestRace、bestScore、settings、lastRun；触发：每圈刷新最佳成绩、比赛结束后以及设置变更时调用 H() 写入；恢复：启动时从 localStorage 读取 pocket-racers:save 并恢复上述字段；不保存未完成的比赛进度。
