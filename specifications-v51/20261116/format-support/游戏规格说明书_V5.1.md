## 0. 使用说明

**重要原则**：

1. **所有内容非必填**：只针对代码中所披露的内容进行**真实还原**，不过度刻意补充、不做完整性填写；代码中未涉及的内容，**可留空不填**。
2. **所有内容均为建议选项**（字段、样例、词表），不作为固定填写的标准，仅作参考——AI 可基于「维度定义 + 样例 + 词表建议」进行补充和扩展，但不得偏离各维度的标准定义。
3. **只还原实现层**（代码可佐证的事实），不还原意图层，不猜测、不评价。

**文档结构**：

1. **内容维度**：游戏规格中有哪些内容维度需要填写；
2. **每个维度下**：维度定义 + 内容说明 + 填写规范 + 填写样例 + 建议词表（如涉及枚举）。

# 第二层：各维度填写规范与样例

## 1. 基础事实

**维度定义**：让读者第一眼知道"这是什么类型、什么操控体验的游戏"，以及它的技术栈。

**内容说明**：客观包含以下信息要素——

- 游戏名称（正式名 / 通用名）
- 玩法类型（大类 + 子类）
- 操控方式（输入方式）
- 视角布局（俯视 / 追尾 / 斜45° / 横版 / 第一人称 / 顶视）
- 画面维度（2D / 2.5D / 3D）
- 技术栈（引擎 + 程序语言）

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 上述内容说明中的各要素 |
| 结论字段 | `game_summary` = 一句话定性 |

**填写样例（Frogger）**：

- 游戏名称：Frogger（青蛙过河）；玩法大类/子类：动作 / 躲避；操控方式：键鼠 + 触屏；视角布局：俯视追尾；画面维度：3D；引擎：原生 Web；程序语言：JavaScript
- `game_summary` = 3D 俯视动作躲避游戏

**建议词表**（可扩展）：玩法大类（动作/休闲/益智解谜/棋牌/体育/竞速/射击/角色扮演/策略/模拟/音乐节奏/教育）；引擎（Unity/Unreal/Godot/Cocos/Cocos Creator/自研/原生 Web/Phaser/其他）；程序语言（C#/C++/GDScript/JavaScript/TypeScript/Lua/其他）

## 2. 资源类型

**维度定义**：游戏中游戏内容元素的资源类型是什么——即在哪个引擎运行下的资源格式。

**内容说明**：客观包含两层要素——

- **游戏内容元素类别**：场景、角色、道具、UI/图标、音频、动画、文本/配置
- **引擎资源体系**：Unity（.prefab/.fbx/.mat/.anim）、Unreal（.uasset/.umap）、Godot（.tscn/.tres/.gd）、Cocos（.fire）、原生 Web（.png/.jpg/.json/.mp3/.glb）等

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 引擎资源体系 + 各内容元素的资源类型清单 |
| 结论字段 | `engine_asset_system` = 引擎资源体系 |

**填写样例**：Web 原生（Frogger / Garden War / Ping Pong Go!）→ 图片 .png/.jpg、配置 .json、音频 .mp3/.ogg、3D 模型 .glb/.gltf

**建议词表**（可扩展）：引擎资源体系（Unity / Unreal / Godot / Cocos / 原生 Web / 其他）

## 3. 核心挑战维度

**维度定义**：游戏核心玩法主要挑战 / 满足人的什么。

**内容说明**：客观列出核心挑战的维度类型——

- 操作/操控类、智力/策略类、养成/经营类、竞技/对抗类、攀比/评分类、剧情/内容类、挑战/过关类、探索/收集类、综合交叉

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 1–3 个主挑战维度（标注主次） |
| 结论字段 | `core_challenge_type` = 核心挑战类型 |

**填写样例**：Frogger → `[operation, challenge]`（操作+挑战型）；Garden War → `[strategy]`（策略型）；Ping Pong Go! → `[operation, competitive, progression]`

**建议词表**（可扩展）：`operation` 操作/操控 · `strategy` 智力/策略 · `progression` 养成/经营 · `competitive` 竞技/对抗 · `comparison` 攀比/评分 · `narrative` 剧情/内容 · `challenge` 挑战/过关 · `collection` 探索/收集 · `hybrid` 综合交叉

## 4. 操控方式

**维度定义**：操控本身的复杂度 + 需要玩家判断的时机 / 策略复杂度。

**内容说明**：客观包含两层——

- **操控方式的类型**（客观枚举）：键鼠（键盘 + 鼠标）、触屏点按、触屏滑动、虚拟摇杆、实体手柄、体感（陀螺仪/加速度）、语音、眼动等
- **操控的构成要素**：输入元素数量（几个按键/手势）、上手步骤数、手速/精准要求、操控复杂度、决策复杂度

**核心原则**：操控复杂度高 → 不适合 APP 端休闲；理想休闲 = 操控简单 + 决策有深度（复杂的是"操控时机"和"策略"，不是操控本身）。

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 操控方式类型 + 各构成要素 |
| 结论字段 | `app_suitability` = APP 端适配（适合 / 需优化 / 不适合） |

**填写样例**：

| 游戏 | 操控方式类型 | 操控复杂度 | 决策复杂度 | `app_suitability` |
| --- | --- | --- | --- | --- |
| Frogger | 键盘方向键 + 触屏滑动 | 简单 | 中等 | 适合 |
| Garden War | 鼠标点击（选中+走子） | 简单 | 复杂 | 适合（决策重、偏硬核） |
| Ping Pong Go! | 触屏拖拽 | 简单 | 中等 | 适合 |

**建议词表**（可扩展）：操控方式类型（键鼠/触屏点按/触屏滑动/虚拟摇杆/手柄/体感/语音/眼动）；手速要求（低/中/高）；操控复杂度（简单/中等/复杂）；决策复杂度（简单/中等/复杂）

## 5. 行为路径

**维度定义**：玩家一局里重复做什么。

**内容说明**：客观指的是玩家在一次核心循环中的动作先后顺序（从循环起点到终点），如"观察 → 决策 → 执行 → 获得反馈"。

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 动作箭头串 |
| 结论字段 | `core_loop` = 核心循环 |

**填写样例（Frogger）**：观察 → 跳跃躲车 → 乘筏 → 吃虫 → 进码头 → `core_loop` = "观察→跳跃→乘筏→进码头"

## 6. 游戏路径（关键节点 + 流失风险）

**维度定义**：从开始到结束的流程 + 每个关键节点的潜在流失风险点。

**内容说明**：客观指的是游戏从启动到结束的完整流程节点，常见节点为：启动 → 主菜单 → 开局 → 进行中（各阶段）→ 结算 → 重开/退出；每个节点标注时间点与潜在流失风险。

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 时间轴 + 关键节点 + 潜在流失风险 |
| 结论字段 | `churn_risk` = 主要流失风险（节点 + 原因） |

**填写样例（Frogger）**：

| 时间 | 关键节点 | 潜在流失风险点 |
| --- | --- | --- |
| 0–5s | PLAY 进入，5 命开局 | 无新手引导，新玩家不知操作 |
| 5–30s | 首次过马路躲车 | 难度陡增，反复被撞挫败 |
| 30–60s | 乘筏过河 | 落水惩罚，节奏难把握 |
| 60s+ | 填码头、过关循环 | 内容重复，新鲜感下降 |

`churn_risk` = 过河乘筏（节奏难把握）

## 7. 成长路径

**维度定义**：玩家如何推进变强。

**内容说明**：客观指的是玩家推进/变强的途径，常见要素为：关卡递进、等级/属性成长、技能解锁、道具/装备获取、收藏图鉴、排行榜名次。

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 成长链条箭头串 |
| 结论字段 | `progression_loop` = 成长闭环（有 / 无） |

**填写样例（Frogger）**：过关换场景 → 木筏缩短难度升 → 三档难度 → 冲击最高分 → `progression_loop` = 有

## 8. 核心闭环（目标-规则-反馈-激励）—— 需详细

**维度定义**：游戏是否具备"明确目标 → 明确规则 → 达成反馈 → 奖励激励 → 下一目标"的完整闭环。

**内容说明**：客观包含五个构成环节——

- **目标**：短期 / 中期 / 长期目标
- **规则**：达成目标的玩法规则
- **反馈**：视觉（特效/动画/弹出/镜头）、听觉（音效/音乐）、触觉（震动）
- **激励**：分数、命数、道具、货币、解锁、收藏
- **闭环**：达成 → 反馈 → 激励 → 下一目标 → 再达成

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 目标、规则、反馈、激励、闭环 |
| 结论字段 | `loop_completeness` = 闭环完整度（完整 / 部分 / 缺失） |

**填写样例（Frogger）**：目标（短=跳进空码头/中=填满5码头/长=冲最高分）；规则（逐格跳跃躲车、乘筏过河）；反馈（视觉=过关特写+100分弹出、听觉=音效）；激励（过关+1命、换场景、连击倍率、刷新最高分）；闭环（吃虫→倍率→更高分→冲最高分→重玩）→ `loop_completeness` = 完整

## 9. 玩法规则

**维度定义**：核心循环、玩法规则、目标与进度。

**内容说明**：客观包含规则的构成——核心循环（玩家重复的动作）、操作规则（怎么操作）、胜负判定（怎么赢/输）、特殊规则（如升变、王车易位、吃过路兵）、结算规则（怎么计分）。

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 核心循环、规则、目标进度 |
| 结论字段 | `playability` = 可玩性（可玩 / 不可玩） |

**填写样例（Frogger）**：核心循环 = 观察车流→跳跃→落点；规则 = 过马路躲车、乘筏过河、进空码头 → `playability` = 可玩

## 10. 数值配置

**维度定义**：影响玩法的关键数值。

**内容说明**：客观列出数值的类型——生命/命数、分数、倍率、难度系数、概率、时长、距离/速度、货币/经济数值。

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 命 / 分 / 难度等关键数值 |
| 结论字段 | `key_numbers` = 数值要点 |

**填写样例（Frogger）**：5 命起始、过关 +1 命；前进 +10、吃虫 25/100/250、倍率 ×5；三档难度 → `key_numbers` = "5 命 / 三档难度"

## 11. 关卡配置

**维度定义**：关卡结构、递进规律、难度曲线。

**内容说明**：客观包含关卡设计的要素——关卡布局（地图结构）、关卡目标、障碍/敌人、奖励物、关卡数量、递进规则、难度参数/曲线。

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 结构骨架、递进规律、难度曲线 |
| 结论字段 | `level_structure` = 关卡结构 |

**填写样例（Frogger）**：草地→5车道→岛→5河流→5码头；5 场景循环，Stage2 起难度升 → `level_structure` = "草地→公路→河流→码头"

## 12. 系统设计

**维度定义**：功能系统清单、UI 流程。

**内容说明**：客观包含两层——

- **功能系统类型**：任务、成就、排行、商店、社交/好友、存档、背包、图鉴、赛季
- **UI 界面类型**：主菜单、HUD、结算页、弹窗、商店界面、设置界面

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 功能系统清单、UI 流程 |
| 结论字段 | `system_completeness` = 系统完备度（完备 / 基本 / 缺失） |

**填写样例（Frogger）**：难度/音效/摇杆开关、最高分存档；UI = 标题→HUD→结算→过关弹窗 → `system_completeness` = 基本

## 13. 主题化包装

**维度定义**：游戏的题材 / 世界观包装。

**内容说明**：客观包含两层——

- **文字层**：世界观设定、剧情/叙事、对话、命名体系
- **美术层**：场景美术、角色美术、道具美术、图标、UI 美术（资源类型 + 内容 + 数量）

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 文字层、美术层 |
| 结论字段 | `theme_position` = 题材定位 |

**填写样例（Garden War）**：蚂蚁 vs 蜜蜂昆虫拟人化；场景 1 种、角色模型 6 种 → `theme_position` = "昆虫拟人化"

## 14. 养成系统 + 经济系统

**维度定义**：玩家如何成长、经济如何循环。

**内容说明**：客观包含两层——

- **养成要素**：等级、技能、装备、收集、解锁
- **经济要素**：货币类型、产出途径、消耗途径、经济循环（产出 → 消耗 → 回收）

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 成长链条、经济循环方向 |
| 结论字段 | `progression_loop` = 成长/经济闭环（有 / 无） |

**填写样例（Ping Pong Go!）**：过关得宝石（普通 10/末关 25）→ 商店解锁球拍 → `progression_loop` = 有

## 15. 角色 / 单位设定

**维度定义**：有哪些角色/单位、各自定位（玩法层面）。

**内容说明**：客观包含——角色/单位数量、各自属性、各自能力/技能、各自定位（玩法层面）、角色间关系。

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 角色清单 + 一句话定位 |
| 结论字段 | `roster_summary` = 角色阵容 |

**填写样例（Garden War）**：6 种棋子，对应昆虫模型与走法（兵/马/象/车/后/王） → `roster_summary` = "6 种棋子"

## 16. 商业化

**维度定义**：靠什么变现。

**内容说明**：客观列出变现方式的类型——广告（激励视频/插屏/banner）、内购（道具/货币/皮肤）、订阅、买断、付费点。

**填写规范**：

| 项 | 说明 |
| --- | --- |
| 填写内容 | 变现模式、付费点 |
| 结论字段 | `monetization` = 变现模式 |

**填写样例**：Ping Pong Go! → 广告（Poki SDK）；Frogger → 无变现 → `monetization` = 广告 / 无

**建议词表**（可扩展）：`ads` 广告 / `iap` 内购 / `subscription` 订阅 / `premium` 买断 / `free` 免费
