# Web 小游戏复刻中心

可运行的本地首版：管理站点、SQLite 控制平面、多工具接入 API、独立试玩服务、独立游戏 Git 仓库，以及 REA / AI 执行器。

## 启动

需要 Python 3.11+、Git。后端和前端不需要 pip 或 npm 依赖。

```powershell
./start.ps1
```

或在任意支持的操作系统上：

```sh
python server.py
```

- 管理站点：<http://127.0.0.1:8765>
- 独立试玩端口：8766
- 默认仅监听本机。当前管理会话是本机工作台模式，不是多租户公网身份认证。
- 原型演示与真实数据库完全分离。演示数据不是已完成的抓取或复刻结果。

公司部署时使用反向代理、TLS、SSO/身份网关，并配置独立试玩域名及对应 CSP。不要直接把本地管理模式暴露到公网。

## 目录

| 目录 | 用途 |
|---|---|
| `web/` | 中文管理界面和独立的演示数据 |
| `controlplane/` | 事务存储、任务租约、状态机、版本与 Git 集成 |
| `executors/` | 独立执行程序、REA 适配、AI 接口和测试用游戏 |
| `game-library/` | 独立 Git 仓库；运行时自动初始化，不包含在平台仓库中 |
| `data/` | SQLite 数据库、不可变原始包与运行产物，默认不进 Git |
| `docs/` | 功能设计、接口和运维说明 |
| `tests/` | 控制平面与边界条件测试 |

## 使用顺序

1. 在真实空间的「工具接入」注册采集或执行工具，妥善保存只显示一次的 token。
2. 手动录入候选，或经 API 提交候选。采集工具可提交源码资源包。
3. 创建批次并启动；支持任务领取、进度回传、独立租约与超时重派。
4. 执行器先做 REA 分析。可运行源码整理后进入 A 路径，无法恢复才转 B 路径。工具或输入缺失是阻断，不冒充恢复失败。
5. 结果进入待验收，统一源码提交到游戏仓库。人工确认玩法、画面、使用范围后入库。
6. 发布通过验收的版本，或切换回先前已通过的版本。已发布游戏的运行不依赖执行器在线。

## 执行器

见 [执行器说明](executors/README.md)。Windows 可执行 `./setup-executors.ps1`，其他环境进入 executors 后运行 `pnpm install --frozen-lockfile --ignore-scripts`。REA 与浏览器验证依赖在执行器目录内安装，不修改全局 Agent 配置。

AI 分析与生成需要自行配置兼容服务地址、模型和 API key。缺少配置会真实进入「待处理」，不会返回假成功。当前运行器针对静态 Web 游戏；复杂打包、引擎导出和二进制资源由独立适配器扩展。

当前不会自动浏览全网或启动首批 30 款，网络采集由接入程序显式提交；30 款的选品与正式执行属于下一阶段。

## 测试

```sh
python -m unittest discover -s tests -v
python -m unittest discover -s executors -p test_worker.py -v
```

## 迁移

平台源码和 `game-library` 分别迁移。停止写入并备份 SQLite 与整个产物目录，推送游戏仓库完整历史到空的公司 Git 仓库。`.env`、token、日志、原始抓取包不进入源码仓库。详见 `docs/` 运维说明。
