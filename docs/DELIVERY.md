# 前四阶段交付说明

## 阶段一：功能、UI 和交互

已实现8个可交互页面：看板、候选游戏、小游戏库、批次、任务、验收、接入、来源规则。参考站为 AI 游戏中心，实看为近黑背景、紫色主操作、明亮游戏图像。当前 UI 沿用该方向，源码与视觉规范在 web/ 和 DESIGN.md。

演示模式默认展示12条明确标记的虚构设计记录和游戏插画，不是第三方游戏截图。切换「实时数据」可查看实际数据库；两个空间的数据修改互不影响。选择、搜索、批次、验收、版本操作和错误反馈均可操作。

## 阶段二：控制平台与多工具接入

已实现事务持久化、Bearer 工具凭证、能力权限、候选规范化去重、多来源追溯、原始包上传、独占任务租约、超时回收、进度事件、幂等、审核、版本发布与回滚。已注册但未心跳的工具显示未连接。状态由真实 API 提供，不使用模拟倒计时充当执行结果。

当前是可运行的本地首版。上公司服务器前还需对接公司身份认证、域名、存储和隔离运行环境；不是已部署的公网多租户服务。

## 阶段三：集中源码

game-library/ 是独立 Git 仓库。每个提交的游戏产物都建立不可变版本目录并关联 Git SHA。代码下载、历史追溯和旧版本发布均使用同一记录。平台源码与该仓库分别迁移；运行产物和 SQLite 独立备份。

## 阶段四：REA 与 AI 双路径

执行器是独立程序，REA 在项目内锁定安装，不依赖平台网页打开。REA 的静态分析与来源包整理经过真实工具调用；测试游戏经过浏览器得分、胜利和重开断言，产物上传并进入真实 Git 与试玩服务。

AI 路径包含观察资料→规格→生成→浏览器验证→有限修复→待验收。兼容模型 API 已实现。自动化测试用明确标记的本地假模型验证失败与修复控制流，不能代表真实模型效果。目前实际模型 endpoint/model/key 尚未提供，真实调用需配置 executors/README.md 中的环境变量；缺配置会进入阻断状态。

## 当前没有执行

未选择、下载或复刻首批30款第三方游戏。真实空间里的「系统自检」游戏由本项目自建，仅用于验证前四阶段，不计入正式试点。未设置公司 Git remote，也未推送代码到任何外部仓库。

## 验证入口

- 后端：python -m unittest discover -s tests -v
- 执行器：python -m unittest discover -s executors -p test_worker.py -v
- AI控制流：python -m unittest discover -s executors -p test_ai_integration.py -v
- 界面：web/check.cjs
- 实际端到端：executors/integration_selftest.py（重复运行不会默认新增版本）

首次交付保持本地服务可打开。停止服务后可通过 start.ps1 或 python server.py 再次启动。
