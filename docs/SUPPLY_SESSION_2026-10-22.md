## 协议前提（需双方确认）

现有 template-supply-client 1.0.0 使用供应方 app_id + 授权码的 HMAC 认证，并由下游通过 archive_url 拉取 ZIP。这不是微信 AppID；接口也不是 multipart 文件直传。

联调前请下游确认：

1. 使用哪个 HTTPS 基址，供应方 app_id 与授权码如何交付；管理页的 12 位指纹。
2. 哪个 HTTPS 文件主机由哪一方提供、如何挂载/上传、是否已登记白名单。可以由公司或下游提供，无须采购专门存储。
3. 是否提供替代的文件直传/免供应方认证协议。如果有，需提供正式接口文档，不能按猜测改签名或省略必填字段。
4. 使用正式环境时，测试 submission 的运营确认人、配额、是否允许上架与测试数据清理安排。

## 联调前本地准备

日常操作在现有小游戏平台完成，无需运行单独程序：

1. 打开“工具服务 → 下游模板供货服务”，填写并保存接入配置。
2. 点击“检查接入与游戏”：检测供应方身份，并只读检查平台内最新可见版本的静态结构和分发声明。
3. “查看检查结果”列出具体游戏、版本与阻塞原因。结构通过不代表玩法、下载白名单或授权已验证。
4. 游戏在验收中心人工验收通过后自动创建供货任务；“查看供货任务”查看推送、下游状态和问题。

下列命令与“信号收集”样例仅用于开发人员隔离回归，不是新产品，不导入平台，不代替真实游戏流程。

在项目目录执行：

```powershell
.\tools\check_supply.ps1 -Command rehearse
```

这会运行隔离供货测试、离线 file:// 样例试玩、准备 ZIP、只读扫描现有版本并检查配置。不会验收真实游戏、写生产游戏状态、推送下游或将测试作品入库。

准备产物：

- `data/supply-readiness/supply-probe.zip`：稳定文件名、根 index.html、无需构建、无外部请求。
- `data/supply-readiness/submit.draft.json`：待确认的请求草稿，授权默认未声明，不能原样提交。
- `data/supply-readiness/audit.json`：现有游戏最新版本的包结构与供货声明缺口。
- `data/supply-readiness/status.json`：离线签名与配置检查。
- `qa-output/supply-fixture.png`：样例运行证据。

样例支持开始、收集成功、重开，桌面和手机可运行；它是本任务编写的接口验证作品，不代表真实游戏质量。

## 当天操作顺序

1. 在服务器终端运行 `.\tools\configure_supply.ps1`，交互输入已获配置，授权码不会显示或进入命令历史。保存到 Git 忽略的 `data/supply-config.json`，仅当前 Windows 用户和 SYSTEM 可读。运行服务若使用其他账户，需由部署人员按需授权该服务账户。环境变量优先于配置文件。
2. `.\tools\check_supply.ps1 -Command status`：配置应完整且无格式错误。
3. `.\tools\check_supply.ps1 -Command online -Fingerprint <管理页12位指纹>`：先核对本地密钥指纹再调用 whoami；不会提交游戏。
4. `.\tools\check_supply.ps1 -Command probe-download`：把无第三方游戏内容的样例 ZIP 写入已配置分发目录，并以 HTTPS 直接 GET 验证字节摘要。该探测不是下游网络测试，下游仍需验证其网络出口与白名单。
5. 指定一个拟供货版本，确认真正的静态工程、操作路径、限制和分发授权。由执行器或入库流程附带 `report.supply`，人工试玩后通过验收，观察自动任务。不要为联调重复验收已有真实游戏。
6. 记录 submission_id；核对 queued、队列位次、状态推进和 notice。人工环节由下游运营确认；没有该确认就不能声称发布完成。
7. 与下游在双方同意的测试记录上验证问题回传与新包修复。不要用真实游戏故意造失败；本地已模拟超时、重复受理、鉴权失败和分页问题。
8. 完成后导出非敏感记录：版本号、ZIP SHA-256、submission_id、extraction_id、关键状态时间、问题码、template_id。授权码和签名不进入记录。

## 判定口径

- **本地模拟可联调**：签名向量、序列化/鉴权协议、受理后响应丢失的幂等重试、重启恢复、问题分页和样例运行检查通过。
- **在线接入就绪**：还需 whoami 成功、指纹匹配、下载连通性与下游白名单确认。
- **真实交付成功**：指定已验收且有授权的版本被下游受理并按双方目标完成后续阶段。模板统计依然按产品要求留空，不用模拟结果填数。
