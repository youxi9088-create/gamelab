## 共享流程补齐

1. 待验收阶段准备独立供货副本，检查授权、交付配置、资源闭合、外部请求及明确密钥特征。只记录准备结果，不批准验收、不提交下游。

3. 保留提交 ID、不可变元数据、包摘要和已验证 URL，未知提交结果不得生成新请求或盲目重传。
4. 按 1.0.1 的状态间隔跟踪；历史终态允许一次性状态校准，之后终态停止轮询。显式同步只读取原提交，不重新供货。
5. 下游自动核验、模板登记与上架试跑分别记录；本地能玩不表示模板可改造，下游失败不撤销本地验收。
6. 强密钥检查不按普通 password 字样定罪；ZIP 超高压缩比文件可无损保存为 STORED，保持文件内容和摘要真实性。

- 原引擎及运行包类型与可移植性分开。Cocos 动态执行等能力缺口不能通过改标签解决。
- 授权必须来自版本资料或用户明确授权；不能把旧脚本的默认归属推广为全库授权，不能删除来源来规避版权问题。
