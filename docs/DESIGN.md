# 功能与 UI/UE 交付说明

## 导航与信息层级

| 页面锚点 | 用户目标 | 主要交互 |
|---|---|---|
| `#overview` | 判断今日产出与需处理工作 | 指标、趋势、近期任务和游戏卡片 |
| `#candidates` | 从多工具提交中选品 | 游戏截图、搜索分类、查看来源、选择进入批次 |
| `#library` | 找到可复用的游戏 | 卡片浏览、查看详情、在线试玩、版本与源码 |
| `#batches` | 管理一组游戏 | 新建、启动、暂停、恢复、查看进度 |
| `#jobs` | 知道游戏卡在哪一步 | 阶段、执行工具、路线、报告、异常与重试 |
| `#reviews` | 检查产出是否可入库 | 原版与产出对比、试玩、验收勾选、退回修复 |
| `#tools` | 接入外部程序 | 注册能力、一次性令牌、启停与接口说明 |
| `#settings` | 管理来源和处理参数 | 来源登记、启停、并发和租约配置 |

中文内容、明亮底色、紫色主操作、圆角内容卡片；大幅游戏画面用于选品与游戏库。管理页面通过状态、步骤和关键操作提高信息密度，不把日志作为主要内容。参考站为 https://ai-game-web.new.ndhy.com/games ，没有声称逐像素复刻参考站。

## 操作闭环

1. 工具提交候选，平台规范化来源 URL，保留多工具来源记录。
2. 管理员选择候选、创建批次、启动；工具领取 REA 阶段任务。
3. A 路径提交可运行整理结果；B 路径先转 reconstruct，再由相应工具领取。
4. 产物成为待验收版本，并已有 Git 提交；人工检查玩法、画面和使用范围。
5. 验收后入库，可单独发布；发布旧版即回滚，已发布内容不依赖工具进程。

## 数据与状态说明

演示模式仅演示 UI 和工作流程，数字、截图与游戏不得混入真实生产成果。切换实时模式从 /api/state 获取本机真实记录。真实空库显示空态，引导提交候选；不自动用演示数据补满。

游戏来源截图与复刻产出截图应标注所属版本。没有真实产出时不展示“已完成复刻”的暗示。截图查看、原站试玩、产出试玩和源码下载各有独立入口。

业务状态包括草稿、待处理、执行中、待验收、已验收、已发布、部分需处理、阻断、失败、暂停。暂停表示不再派发新任务，不表示强制终止正在运行的程序。

## 统计口径

日期使用北京时间。发现按候选首次创建计数；获取按首次保存输入包或首次形成有效产物计数；入库按候选首次验收时间计数。版本更新不算新增游戏。待验收和异常是当前积压存量，不是今日累计。

恢复与复刻分别来自 A/B 路径进入待验收的完成记录，需与“已验收入库”区分。重试和新版本不得制造额外新增入库数量。首批 30 款的失败样本保留，不通过替换而隐去失败分母。

## 后续设计扩展

企业角色与审批权限、复杂筛选保存、定时采集、截图逐状态对齐、视觉差异标注、真正费用面板、工具级并发和自动分派规则仍可扩展。当前验收用人工确认，不声称已有自动玩法完整度评分。
