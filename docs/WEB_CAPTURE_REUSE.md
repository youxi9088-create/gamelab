# 三款 Remix 游戏转换：共享修复与复用规则

## 与模板供货衔接（2026-11-03）

离线运行包、可修改源码与下游模板上架是不同交付阶段。依赖应本地化并保留出处；游戏逻辑按职责拆分，第三方库独立存放。源码静态请求扫描仅覆盖可识别调用，必须与实际运行网络证据结合；不能把扫描无发现当成完整无外联证明。供货准备在独立副本进行，不覆盖历史产物、不补造授权、不自动验收。报告与共享修复范围见 `SUPPLY_PIPELINE_GAPS_20261103.md`。

## 适用目标

输入不同站点的 Web 游戏，保留原代码与资源，生成可离线运行包，再以真实输入和截图核对基础玩法。以下记录来自本地版本与执行证据，不代表所有引擎或网站已验证。

## 复用边界

以上是按技术证据组合的共享能力，禁止按游戏名、ID或截图路径特判。原站SDK适配仍按明确声明选择，不代表所有版本兼容。未知脚本混淆、动态拼接地址、CSS复杂语法、后端接口和未访问关卡仍可能需要探索。不可把去掉URL查询参数、屏蔽字体/图片或伪造登录作为成功。

这三个同站样本证明这些修复对实际问题有效，尚不是跨站成功率评估。可组合契约注册库、发现阶段全部资源移交、跨站固定样本矩阵尚未完整完成；不得宣称已具备自动学习任意游戏契约能力。

## 回归

- tests/test_declared_static_recovery.py：精确声明、查询参数、排除未知和POST、自动复验与停止重复。
- tests/test_stylesheet_rebase.py：相对字体/CSS引用来源与映射更新。
- tests/test_conversion_checkpoint.py：不可变历史、修复检查点、身份绑定和摘要。
- tests/test_runtime_bindings.cjs：原生浏览器动态图片与背景、嵌套部署、不同查询参数不误匹配。
- tests/test_resource_retry.cjs：有限GET重试，POST与非传输错误不重试。
- tests/test_static_resource_evidence.cjs：静态引用证据与动态模板排除。
- tests/test_runtime_recovery.py：原始证据保留、回滚、连续依赖与实际浏览器复验。

再次遇到同类失败时，先看runtime.json、acquisition.json、static-recovery.json和检查点，不重新针对游戏编写方案。不保证所有问题消失；新结构需保留失败样本并补共享能力和隔离回归。

## 2026-10-30：本地共享规则与资源移交更新

- runtime-contracts.json 是共享规则注册表，revision 标记库版本，单规则保留 id/version、group、requires/excludes、优先级、adapter/provides。加载器与宿主分别组合。首批注册 Ruffle、Cocos 2、Defold、通用浏览器和声明的 Remix SDK，不将同网站等同同引擎。
- runtime-contracts.cjs 在采集到入口源码后匹配。规则冲突/证据不足继续通用浏览器探索；未知结构仅生成未验证候选记录，不自动把AI生成代码晋升为可信适配器。源哈希记录本游戏来源，不作为跨游戏匹配条件。
- 每次执行 runtime-contract.json 记录命中、未满足条件、冲突、来源和阶段历史，证据进入 converted/evidence；检查点携带该记录。最终玩法验证追加自身证据，不把启动验证当成玩法通过。不追溯改写历史游戏版本。
- acquired-resources.cjs 在发现浏览器中保存受限静态响应；按来源帧、精确URL、长度与SHA-256验证后，供通用浏览器及静态模块采集复用。最多300文件、80MB，单资源20MB；未取得或不匹配就正常下载，不猜查询参数。
- 静态模块的 urllib/curl 传输失败同样接入浏览器网络回退，HTTP明确拒绝不切换传输冒充可取得；这补齐了 esm.sh 模块分支此前的覆盖缺口。
- 观察结果新增 document_focused、focused_tag、pointer_locked、pointer_lock_target，供实际输入诊断使用，不以焦点或指针锁定状态单独认定操作成功。
- report_capture_funnel.py 是只读统计命令，按来源站点列出当前已启动任务、产物、启动证据、交互证据、待验收及人工完成。当前状态含历史代码结果与重排队任务，不可作为新代码A/B成功率。logs/capture-funnel-20261030.json 是本次快照。

验证包括真实浏览器离线外链拒绝、Defold持续按键与存储、静态资源恢复、动态CSS、来源变化/冲突/证据不足规则矩阵和发现快照校验。规则矩阵为隔离样例，不宣称真实跨站游戏成功率已经提高；真实游戏样本仍是本次三款Remix。

本地后续独立执行器会读取这些新文件。常驻管理服务重启仍被执行策略阻止，未使用其他方式终止原进程。无自动生成任意引擎适配代码、恢复任意后端或完整通关保证。

## 跨源资源查询参数身份与样式类型（2026-11-02）
- 适用：真实采集报告出现 Resource query collision，跨源同路径URL带不同查询参数并返回不同字节，如字体样式选择和图片缩略尺寸。共享capture-resource-paths.cjs将完整origin+pathname+search纳入跨源路径摘要，精确查询身份不同则独立保存；fragment不代表新的HTTP资源。
- script保留.js后缀；浏览器实际识别的stylesheet没有.css后缀时追加.css，使离线静态服务按CSS类型返回。使用真实resourceType，不按网站或游戏名称分支。映射仍使用原始精确URL，真实字节及SHA保留，既有包不覆盖。
- 同一个精确URL若本轮返回不同字节仍阻断，不能用任意覆盖隐藏变化。同源包目录布局保持原样；同源查询参数冲突仍需单独证据与适配，不把本修复推广为已覆盖。
- 6项远端隔离测试覆盖查询参数区分、fragment一致、样式后缀、原本地布局、脚本后缀和非法路径拒绝。匹配任务仅在无手动暂停、批次运行或自动attention且无另一活动任务时，通过原任务重试接口恢复；离线与玩法验证仍独立执行。

## 执行器平台回调通道（2026-11-02）
- 多个已有草稿的待完善任务因URLError/WinError10061退出，需区分平台回调连接与游戏运行错误。共享platform_transport对loopback控制面明确直连，不继承外部代理；外部平台仍沿用原代理策略。
- 仅连接尚未建立即被拒绝时最多4次、0.5/1/2秒有限退避，复用同一个请求。HTTP拒绝、超时、连接重置不由该底层自动重放；Client已有幂等键及保护下的传输重试保留，连接拒绝不叠乘重试次数。错误只记录无凭据/无查询串的目标路径。
- 连接拒绝重试耗尽标记为控制面基础设施故障，不再把它交给游戏AI反复改包；当前运行证据和历史版本保留。新任务子进程自动加载共享修复，不重启原执行服务或终止其他任务。
- tests/test_platform_transport.py的5项隔离测试涵盖相同POST复用、拒绝/超时/重置边界、有限次数及诊断脱敏、仅loopback绕过代理，以及真实本地监听器延迟启动后成功接收且只收到一次请求。
- 恢复原任务仅限无手动暂停/无其他活动任务、已有草稿且有原运行基础、当前因10061失败，保留检查点重试；旧runtime.passed只作恢复资格，不作为新轮次成功证明，仍须实际玩法和交付门禁验证。

## 验证器收尾与控制面错误传播（2026-11-02）
- 适用特征：运行证据已写出，但验证进程超时未退出；或游戏复验期间平台事件/回调连接拒绝。运行检查通过不能替代玩法完成和进程正常收尾。
- 验证器清理不再等待全部路由回调后才关闭浏览器。共享 verification-cleanup.cjs 使用 unrouteAll(ignoreErrors)、关闭自身浏览器、关闭自身 HTTP 服务及其连接；各步异常仍继续清理其余对象，最终抛出真实清理错误。清理失败将 runtime.passed=false 并记录 infrastructure-cleanup，不放宽游戏验收。不得关闭其他任务的浏览器或服务。
- 远端实际 Chrome 隔离复现旧 wait 在未完成路由回调上持续等待；新流程144ms完成，浏览器断开、HTTP监听关闭；异常清理继续释放服务器，2项通过。此证据说明共享能力缺口，不代表所有历史超时均为同一根因。
- control_plane_transport 在自动诊断入口、静态补抓重验、AI重验及最外层均直接传播。先保留已有修复回退和真实证据，再中断游戏诊断；不能把新平台错误吞回旧游戏错误，继续消耗AI或修改玩法。25项隔离 Python 回归通过。
- 8765原执行服务当前仍可毫秒响应，但任务曾实报4次连接拒绝；重试与分类并不等于已消除服务端间歇性拒绝的根因，继续检查端点、监听和并发。
- 恢复原任务使用平台接口与原检查点，尊重手动暂停和全局并发。典型跟进使用同数据库且正常鉴权的现有18769接口，仅单次目标认领，不启动周期监控；不重复认领已运行任务，不直接修改验收状态。
