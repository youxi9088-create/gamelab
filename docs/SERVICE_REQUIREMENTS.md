# 复刻平台服务与产品要求

## Remix Three 静态移植与交付（2026-10-22）

- 用户要求 Hyper Strike 由云端平台任务还原，开发会话只维护共享执行能力，不制作或手工导入游戏成品。已有普通 iframe 即使因 SDK 网络故障尚未出现画布，也可按唯一的已声明 Remix 宿主线索获取原始 HTML；只有离线真实浏览器成功才保存可试玩版本。
- 首个模块适配范围为显式 importmap 的 Remix Three 运行契约，递归保存 esm.sh 明确模块引用及原页面声明的媒体资源，校验公开 HTTPS、数量和体积，保留原始文件和哈希；不按游戏名分支，不承诺任意 Three.js 游戏适配。替换为共享本地宿主，支持真实得分结算、重开、本地存档；不伪造在线账号、购买或排行榜。
- 继续使用平台配置的 AI 和隔离浏览器验证代表性玩法，保留实际操作、截图、用量与缺项。供货静态包遵守 template-supply-client 的入口、体积、文件数量、语义文件名、引用与真实验收步骤要求，技术通过不替代功能验收。
- 用户统一指定移植游戏的供货权利人填写 gcy，声明允许抽取模板。记录为用户提供的授权信息，不推定已确认衍生作品发布范围；正式供货的完整许可声明仍按协议检查。
- 静态模块依赖使用 JavaScript 语法树识别，字符串、注释和模板文案不能当成 import。发布期间禁用计划任务自动恢复，切换后核对实际执行器进程所属版本，避免旧进程继续领取任务。
- Web 续作结束时由平台模型根据本轮源码和实机证据返回中文游戏档案，保存进不可变版本并生成 Markdown 游戏规格说明书；未验证机制、内容规模及移植能力必须保留边界。
- 模块解析以二进制 UTF-8 管道传输，保留 Windows 下的原始换行及 UTF-16 语法位置；出现脚本异常时立即保存堆栈并报错，不只等待画布超时。
- 平台模型同轮请求源码读取和浏览器操作时，二者都应处理；源码读取不能吞掉已提出的实际操作。只有浏览器执行记录可以作为动作完成证据。
- 供货检查区分运行资源的内容哈希文件名与 evidence/verification 内的 JSON 证据记录 ID；证据 ID 不作为不支持构建包的理由，脚本、样式及运行素材仍按原规则检查。
- 共享源码导航保留每项搜索的零命中、总命中数、全文覆盖字符数和源哈希，避免模型看不到查询结果而重复消耗轮次；字面量搜索与别名/动态调用分析的边界必须保留。Three.js 展示标签来源于版本适配证据。
- Web 续作把源码导航保存到版本验证证据，下轮按当前源码哈希重新读取和搜索；源码改变时不继承旧结论。旧轮次只在任务绑定及文件基线一致时重放读取请求。中断仍保留草稿，不把未完成响应作为完成判断；AI 终止响应显示固定协议错误码，避免仅显示 ValueError，同时不暴露提供方原始错误正文。

## 云端统一生产数据、账号与 Git 发布（2026-10-22）

- 生产服务持续运行在云服务器，开发电脑不参与生产执行。平台代码以已推送的 Git 提交为准，发布包从提交生成，不包含工作区未提交文件。生产数据与凭据不提交平台 Git。
- 数据库、游戏产物、游戏源码版本库、执行工作文件和证据归入 shared 统一持久目录；程序发布目录与生产目录分离，通过稳定目录链接兼容旧引用。完整备份包含数据库快照与逐文件校验，不以只备份数据库代替游戏文件备份。
- 账号采用项目内共享数据、角色限制操作。管理员管理账号与配置、验收及供货；操作员提交和处理任务；只读用户仅查看。后端强制授权，密码加盐哈希，会话持久化且可撤销。此前单环境管理员说明由此条升级，无开放注册和跨客户数据隔离。
- 发布前检查活动任务并暂停领取，备份后切换明确 Git 版本，健康检查成功后恢复领取；记录发布版本与前一版本，提供兼容数据前提下的程序回退。不能将程序回退当成破坏性数据迁移回滚。
- 账号操作与新任务记录实际操作者；历史缺失归属不编造。运行监测和定时备份部署在服务器，不依赖开发电脑。异机备份和外部告警接收渠道未配置前必须明确说明边界。
- 本地历史完整归档到云端 shared/history，包含原数据库、游戏文件及独立源码库历史。仅将云端没有的正式游戏及版本导入当前库，保留草稿、已替代等真实状态；不导入旧任务到执行队列，不覆盖云端现有记录。隐藏自检样例只归档。用户目前没有异机备份目标，先保留云端同机备份并明确整机、磁盘故障仍可能造成丢失。

## 任务进度、过程记录与单任务排队（2026-10-22）

- 任务进度以实际阶段、草稿可用性、验证和人工验收状态表达，不把固定90%或执行器心跳数值当作总体完成率，也不预测剩余操作次数。保存草稿不表示验证完成。
- 时间线节点状态对应当前轮次，历史轮次折叠保留；缺少结束证据的步骤不可一直显示执行中，也不能推定成功。Web 续作的运行与玩法验证归入验证节点，结果消息使用中文并绑定实际结束轮次。
- 当前云端全局最多执行1个转换任务，在共享租约领取事务内限制，覆盖自动转换、手动任务、重试及续作。其余按入队时间排队，暂停批次不领取，待人工回复或验收不占执行名额；自动续作回到队尾。页面显示可执行队列位置。该位置不承诺等待时长。
- 推荐玩法说明使用中文，外文来源正文独立保留，调用平台配置的AI翻译并记录独立采集翻译用量，不计入某款游戏转换成本。翻译失败显示中文待翻译提示，不把外文直接展示为推荐说明，也不编造玩法。原游戏专有名称可以保留。

## 门户管理员登录（2026-10-22）

- 门户支持由服务端环境变量 `PORTAL_ADMIN_USERNAME` 与 `PORTAL_ADMIN_PASSWORD` 配置的单管理员登录；两项必须同时设置。没有设置时维持现有仅本机管理模式，不能使用内置默认凭据。当前不提供开放注册、多用户、角色权限、密码重置或账号管理。
- 启用后，管理状态、下载及写操作 API 均需有效的服务端会话；登录、退出分别使用专用接口，管理请求继续校验 CSRF 与 Origin。外部执行工具 Bearer 认证保持独立。
- 登录会话有效 12 小时，HttpOnly、SameSite=Strict；同一来源地址 15 分钟内连续 10 次失败会被限流。会话只保存在服务进程内，服务重启后需重新登录。
- 服务仍仅绑定本机回环地址。登录能力不等于公网多租户、安全反向代理或 HTTPS 部署；远程使用前需另行完成监听、TLS、密钥管理和部署安全设计。

## 延迟广告页与 Web 入口发现（2026-10-22）

- 已观察到的唯一 Web 入口继续进入共享引擎适配，当前支持 Cocos 2 发布包和声明 SWF 的 Ruffle 宿主；按运行代码识别，不按游戏名、ID 或网站目录猜测。采集保留 iframe 父页面来源，避免丢失来源信息导致跳转。
- 新路径保留原文件哈希，采集同源运行代码及公开媒体资源、预加载已声明 Cocos 资源包，将已捕获的绝对引用改为包内相对引用。Ruffle 保留 SWF 与运行引擎，使用独立可编辑播放器宿主；SWF 不宣称恢复可编辑核心源码。未适配的异源接口、未知引擎、容量上限或资源碰撞明确记录失败。
- 大型 SWF/WASM 在请求转交浏览器前保存响应，避免调试缓存淘汰造成假缺包。预加载遇到的缺失资源保留 HTTP 状态与阶段，不能宣称全资源闭合；启动路径仍通过独立离线检查。识别到已有客户端离线初始化契约时可精确关闭远端同步入口，保留原本地规则与存档，不生成虚假服务器数据或广告奖励；补丁保存原始和修改后哈希。Ruffle 静态包通过内容策略禁止外部统计和网络依赖。
- 离线浏览器禁用外网并记录启动状态、截图、缺失请求和异常；通过后保存可试玩草稿，AI 使用实际资源和运行记录分析依赖与二次开发边界，实际用量沿用任务账本。AI 分析失败保留转换产物，不将模型说明当作玩法验收。
- 首次 Web 转换通过离线启动后，保存不可变草稿并由共享任务调度自动续作，使用平台配置的 AI 完成实际操作、阶段结果、继续及适用的存档验证，不再因“尚未验证玩法”要求用户手动续作。已有支持引擎的成功运行报告中，WEB_GAMEPLAY_REVIEW / WEB_VERIFICATION_BUDGET 作为可接续工作处理；真实运行错误、AI 中断、未知引擎及所需材料缺失仍明确阻断。连续 3 轮验证状态和缺项数量未改善，或累计达到 8 段执行时停止自动续作，保留版本、证据和用量；暂停批次不自动恢复。验证齐备进入待验收，人工验收和发布独立，不按百分比直接标记已完成。本轮用户明确要求修复并继续平台真实任务；这属于实际交付，不以生产任务作为开发测试夹具。
- 基础玩法验证以一个代表性闭环为界：实际输入产生阶段结果，能返回可操作界面或继续，并验证适用的保存恢复。已有第一阶段闭环时，不能把新解锁的下一关或新增升级继续列为必须通关项；后续未访问内容写入覆盖边界。续作接收基线已有的真实状态和输入证据，避免把已验证事实当成未执行。
- Web 自动续作向验证模型传递共享交付检查的 pending_delivery 缺项，优先补剩余证据。后端依赖按已验证的代表性流程判断，结合实际请求、结算与保存恢复，必要时读取相关代码；已证明无后端依赖的本地流程可标记不适用并限定范围，不能只凭启动无外部请求判断，也不要求穷举未访问功能。
- Web 续作向平台配置的 AI 传递最近的管理员任务要求，最新要求决定本轮处理范围。已有转换产物与操作记录可复用，但未保存的浏览器会话不能冒充可恢复存档。用户要求从断点继续时须区分产物续作与游戏运行状态恢复；没有运行存档时，经用户明确同意才回放必要操作补剩余验证，不重新采集或转换，也不按进度百分比直接标为完成。
- 已发现引擎的草稿续作由平台配置的 AI 接收真实浏览器截图、输入记录和只读源码片段，提出有上限的鼠标、键盘及刷新动作，执行器记录实际反馈；Cocos 加载中文字未消失不记作启动完成。原采集游戏代码与引擎不可由模型改写，只允许宿主修复；最后一次验证后的新修改或动作不得沿用旧结果交付。基础检查仍需证据，人工验收与发布独立；不是通用自主通关能力，也不借用开发会话生成游戏成品。
- Web 视觉续作在同一隔离浏览器中连续观察和操作，不在每次 AI 调用时重启游戏。每轮最多 20 个新动作，历史前缀只在续作开始时回放，累计最多 100 个；浏览器和 API 等待仍受任务预算限制。模型分析期间游戏继续运行，报告记录实际观察时间；回放后必须重新观察，不假定随机游戏状态完全一致。宿主修复后重开浏览器验证，失败清除成功标记；已验证的部分检查与未完成项分别保留。
- Web 游戏截图记录当前浏览器合成画面及字体状态，不无限等待游戏动态注册的字体完成；截图本身不强制替换字体、改变样式或注入游戏状态。视觉判断依据实际像素，字体仍加载时保留其状态和覆盖边界。
- 同一隔离页面的截图在备用采集方式成功后优先复用该方式，避免每个操作都重复等待已失败的方式超时；仍每次读取实际画面，不复用旧截图冒充当前状态。
- 共享 Web 验证器记录隔离页面 localStorage/sessionStorage 的只读键名、长度和 SHA-256，刷新动作记录前后摘要；不输出存档正文、不写入或注入存档。限制每类最多 100 项、400 万字符，读取失败或超限明确标记不完整。存储保留不等于游戏已恢复同一进度，必须结合实际玩法画面；历史缺记录不能推断存档丢失。当前不覆盖 IndexedDB、内存状态，也不宣称跨版本或跨浏览器存档迁移。
- 续作启动时完整回放历史输入并逐步记录运行状态，视觉证据采集启动和回放结束检查点；新 AI 操作仍逐步截图。报告区分历史回放数量和本次实际截图清单，不把基线拷贝的旧图片当成本次观测。
- AI 网络中断时，已通过实际浏览器检查的 Web 操作和文件保存为未完成草稿，不将网络错误当作玩法失败或成功。旧失败轮次可读取同任务绑定的最后一次通过记录；只有游戏和宿主文件与当前基线逐一哈希一致才恢复其操作前缀，随后重新观察，不能跨基线沿用结论。
- 离线检查观察到实际缺失的相对资源时，执行器最多三次从已记录的原始目录补齐，并重新启动检查；每批最多 100 个、累计最多 250 个，沿用文件数和字节预算，不跟随重定向、不跨原目录、不替换已有文件。保存原始响应哈希及失败检查记录；原站不存在的文件明确阻断，禁止伪造替代资源。自动转换和 Web 草稿续作共用这条补齐路径，二进制资源随本轮租约的新版本快照交付，历史产物不改写。

- Web 入口采集在可见页面出现明确的“跳过广告 / 关闭广告”语义控件时，可以等待控件自身的倒计时结束后仅点击该控件，倒计时最多等待 30 秒；不得点击广告素材、泛化的“关闭”按钮、登录或同意控件。等待及点击结果写入采集证据。
- 同时检查 iframe 的 `src`、`data-src` 与 `data-url`。延迟属性地址属于入口线索；只有实际渲染的游戏画布或其他明确运行证据才记作已观察入口。页面中存在 URL 不等于游戏可访问、资源完整或已验收。
- 当前通用 Web 宿主适配仅覆盖上述明确引擎和既有注册方案。发现 iframe 地址可以避免把“入口线索缺失”误报为“网页没有游戏”，但不能据此自动宣称转换、运行或验收成功。

## 公网单管理员部署（2026-10-22）

- 公网入口由 HTTPS 反向代理提供，平台管理和试玩后端继续仅监听回环地址；管理请求保留 CSRF/Origin 检查，反向代理只转发到固定本机上游。
- 公网管理 API 由门户单管理员会话保护；试玩和运行包路由必须验证同一门户会话，不作为匿名公开静态目录。反向代理保留浏览器 Origin，由服务仅额外允许显式配置的公网站点源。
- HTTPS 部署中的 loopback 试玩地址统一映射为当前站点的 `/play/` 与 `/runtime/` 路由，版本记录与运行包内容不改写；映射不依赖游戏名称或 ID。
- 使用公网 IP 时，TLS 证书必须由公开信任 CA 签发并自动续期；若 CA 采用短期 IP 证书，续期任务和代理重载必须持续运行并可检查日志。
- 内置转换执行器的浏览器探测和真实执行必须使用与仓库锁定 Playwright 版本相配套的 Chromium。Windows 服务环境不可自动挑选系统 Edge；只有显式配置 `BROWSER_EXECUTABLE` 时才覆盖 Playwright 默认浏览器。生产部署应将浏览器安装在服务账户可读写的稳定路径，并由启动任务和健康探测共享该路径。

## AI API 服务接入（2026-10-22）

- 平台 AI 服务支持 Chat Completions 与 Responses API 两种协议；协议由服务配置明确选择，Responses 请求使用 `input`、JSON 输出格式、`max_output_tokens` 与 `store:false`，从响应读取文本和真实输入/输出 Token。
- Responses 对图片与文本分别转换为相应输入类型。任务 API 等待上限为 300 秒，且不超过调用方剩余预算；错误摘要区分超时、HTTP 状态和无效 JSON，不返回供应方原始错误或凭据。
- 共享任务调用对网络中断、超时及可重试 HTTP 状态最多追加一次 API 尝试，每次均消耗任务调用额度并独立记录真实用量；认证、协议和输出格式错误不自动反复尝试。两次均失败时保留已经取得的实际执行证据。
- SSE 在收到终止响应前断流，以及 IncompleteRead / RemoteDisconnected / ConnectionResetError，属于上述有界重试；不将部分输出视为完成。Web 验证报告保留经过脱敏的错误类别；任务调用额度或时间额度耗尽与 AI 服务错误区分，已有成功运行证据的分段预算结束交由共享续作上限控制。
- Responses 使用 SSE 流式请求，只有收到 `response.completed` 后才解析完整 JSON 和真实用量；中断、failed、incomplete 事件及仅有文本增量均不得作为成功结果。兼容返回普通 JSON 的服务，保留任务预算和响应容量限制。这用于减少长响应被中间网关等待超时截断的风险，不保证第三方网关永不超时。
- 可配置额外 actor 授权头。其值作为服务端私密配置保存，不通过服务状态接口返回；留空保留既有值。服务检测使用最小 JSON 请求，状态只记录成功/失败和不含供应方原始错误的摘要。
- 外部代理可能按 User-Agent 过滤服务端请求；平台使用自身标识 `GameLab/1.0`，不发送 Python 默认标识。
- Codex 专用 `models.json` 是 Codex 客户端模型目录，不是平台服务配置；平台 API 以服务配置中的模型 slug 调用，不把目录说明文字、模型提示或工具权限导入平台。

- 记录供货包自身 SHA-256（不能使用现有逐文件聚合摘要替代）、版本/提交/包映射、验收步骤与限制。下载地址必须 HTTPS、主机在下游白名单、可直接 GET 且不重定向，有效期至少 5 分钟；localhost 试玩或下载地址不能用于供货。
- 对接设置支持站内管理员表单写入服务端私有配置；授权码留空保留，不从接口回传、不进入游戏包、日志或 Git，写入前限制文件权限。环境变量仍优先，站内不能覆盖部署环境的值。正式提交前完成官方客户端 selftest、指纹比对、whoami；当前尚未联调。
- 服务端签名遵守 skill 的六段 HMAC-SHA256 协议，实际发送 body 与签名使用字节一致；每次重试使用新 nonce，时间差 ≤300 秒，POST 不带查询串，GET 规范查询串。提交读超时 ≥330 秒。
- 同一供货提交网络重试复用 `submission_id`；改包或形成新交付版本后创建新的 ID，并记录前次关系。提交成功不代表模板生成成功，保留 `extraction_id`、`state_text`、`next_action`、`notice`、队列位置和问题清单。
- 后台轮询：queued/received 每 5 分钟，analyzing/building 每 1 分钟，人工环节每 30 分钟，终态停止；429 按 retry_after 退避。问题按 revision/seq 拉取，revision 改变全量重拉；未知状态或问题码保留原文展示。不能用阶段百分比计算剩余时长。
- `needs_your_fix`/`rejected` 建立供货修复待办，新版本修好后新 ID 提交；`failed` 为下游处理问题，不自动重跑游戏复刻。供货撤回与本地发布/验收分开。
- 已实现：人工验收通过在同一事务内创建版本唯一的供货任务；后台异步生成静态 ZIP、按实际 ZIP 计算摘要、调用 whoami 和签名提交、持久化重试及阶段轮询、同步增量问题；验收中心展示供货阻塞、下游待办与修复建议。历史已验收版本不自动补推；所有入口统一走现有 versions/approve。
- 执行器在版本报告 `report.supply` 提供授权、验收路径和已知限制，正常流程不要求验收人重新填资料。旧版缺资料时可通过供货资料接口补充，不能根据 owned/open 等标签推定可分发许可。
- 本地与下游状态分开：功能通过不受供货错误影响；下游要求改包后走原任务继续修改、新版本人工验收、新供货编号，不自动改旧包或重跑游戏。模板数继续留空。
- 实现边界：基础包检查覆盖根入口、路径/符号链接、文件数/容量、部分禁止扩展名与不支持构建产物；不等于完整安全扫描、离线运行或玩法验证，仍需本地人工验收和下游分析。外部运行服务或 ZIP 内嵌运行包须整理成真正静态工程；不可声称已自动处理所有历史包装形式。
- HTTPS 下载主机/文件目录须由部署环境提供并在下游登记白名单；当前无凭据和公开分发配置，未向下游实际发送游戏。配置说明见 `docs/SUPPLY_INTEGRATION.md`。验证使用隔离数据与模拟下游，不对真实游戏测试性验收或推送。

## 链接批次与执行时间线（2026-10-20）

- “创建批次”主入口接收每行一个游戏链接（1–100 个），提交即启动自动转换；旧候选批次 API 仍保留其草稿/启动语义。
- 链接规范化、去重、候选登记和任务创建在同一事务内。已有活动或完成任务返回原任务，不移动原批次、不重跑；已有失败任务提示在原任务继续。全部重复时不创建空批次。
- 单游戏任务展示识别、获取、分析、适配、测试、入库、验收、发布八节点时间线；执行器通过带租约的 events 接口提交 node/node_status。
- 时间线由共享服务层从事件和版本记录投影，覆盖转换、续作及本地导入。原记录不被改写。历史自由文本只能表示“有记录”；没有逐阶段证据的步骤不推定成功，入库不推定运行测试成功。
- 节点详情保留历次记录、轮次、开始结束时间和有据可算的耗时；现有轮询持续更新。旧执行器无细粒度事件时只能展示现有证据。
- 任务详情去重仅影响展示：当前说明已在时间线或本轮对话中展示时，顶部不再重复；节点原因与节点日志相同时只展示日志。历史任务列表排除当前任务，补充日志按事件 ID 排除时间线已有记录；同轮对话已承载的相同日志文案不再重复，跨轮执行记录仍保留，原始数据不删除。
- 三块内容分工：时间线展示阶段与执行记录（AI 执行汇报折叠附在其后）；代码与资源依赖展示缺项、证据与下一步；沟通区仅展示用户要求、AI 答复和提问。共享消息服务写入用途 kind，状态接口统一投影 presentation；旧消息只按明确提问/工作日志证据归类，其余保留在“历史未分类消息”，不按关键词猜测。完整消息仍传入续作上下文，原始历史不删除。
- 本轮未解决：通用原版适配、自动依赖闭合、多站点定时采集与评分、完整说明生成、跨机发布。不得将链接批次和时间线称为全流程自动化完成。

## 服务边界

### 首版默认交付标准

首版必须还原可辨认的基础玩法闭环，以及该闭环涉及的基础资源、场景、物件、角色、动作、UI。仅能打开页面、加载静态模型或截图成功，不算完成基础还原。

- 玩法：输入操作、核心规则、碰撞/交互、得分或进度、胜负/结束及重开，按原游戏证据列出，不能用泛用模板冒充。
- 资源/场景/物件/角色：优先提取匹配缓存；核对贴图、材质、比例、朝向和作用，不得只替换模型而遗漏基础交互对象。
- 动作：验证待机/移动/转向及玩法必需动作；不能以静态平移代替游动、奔跑等动作。有原动画时优先适配，并记录未绑定轨道。
- UI：优先使用原界面图集、组件和布局，接入真实按钮与状态。不得自行设计一套 UI 替代原界面。未实现的原功能应明确记录，不得做成看似可用的空按钮。
- 交付报告提供 `foundation_checks`，包含 `gameplay/resources/scene/objects/characters/animation/ui` 七项，逐项记录 `status`、`reason` 和产物内 `evidence` 路径。无角色等不适用情况必须说明。
- 共享检查器 `controlplane/delivery_requirements.py` 检查报告完整性及证据文件存在；它不等于自动判断视觉一致或玩法还原程度。缺项列为“基础还原未完成”，不能进入待验收；最终仍需人工试玩。
- 已有不满足标准的版本保留历史，不据此宣称满足新标准。当前任务继续补齐动作、UI 及玩法差异。

### 默认首版流程：缓存和原资源优先

提交链接 → 识别 AppID → 检查本机匹配缓存（代码包与该游戏的本地资源目录）→ 提取资源并建立来源清单 → 原资源适配 → AI 生成/重写逻辑 → 验证资源引用与浏览器运行 → 第一版入库待验收。

- 缓存检查是默认前置步骤，不需要用户追加“使用原版资源”。有可用角色/场景素材时，第一版必须使用；生成和修复均不得覆盖或丢弃原资源。
- 平台执行器负责读取缓存、解包和向模型传入素材清单；AI 文本推理服务仍不直接操作本机文件。不能把模型没有文件工具当成要求用户手工导出缓存的理由。
- 无匹配缓存：记录检查结果，提示先打开原游戏产生缓存，再重试；默认不交付替代素材版。
- 有缓存但未解析：明确“资源解析待适配”，保留证据，不能静默转成原创 Canvas 图形，也不能伪称已复用原资源。
- 当前内置提取器支持 wxapkg 内直接可用的常见图片与音频。下载缓存定位为 `applet/local/{AppID}`。Unity 资源可通过 `executors/unity_resources.py` 将明确选择的 bundle 中 Texture2D 转为 PNG、Mesh 转为浏览器几何 JSON，记录来源哈希、选择范围及失败项；需配置 `REPLICA_UNITYPY_PATH` 或安装 UnityPy。材质对应、骨骼动画、专有图集和玩法适配仍需处理，不能把通用导出等同于全自动游戏转换。
- 本地资源适配可使用 `tools/import_task_adaptation.py` 挂回原任务：创建不可变新版本、保留旧版和沟通记录、清除过时提问，不另建重复任务，不自动验收。运行验证和七项基础交付检查都通过后才进入待验收；使用 `--save-draft` 保存尚有缺项的可试玩草稿时，任务保持阻塞并列出缺项。当前大鱼吃小鱼动作与 UI 适配版属于此类草稿，不能视为基础还原完成。
- 资源包大小、文件数量受当前自动产物通道约束，超出限制停止并说明，不静默删减。
- Unity 缓存导出必须支持 Windows 超长路径；按字节读取 bundle，避免解析库把超长文件名当成不存在的输入而漏掉资源。Prefab 包不含模型或纹理时，要继续检查依赖包，不能仅凭该包导出为空就认定无原版资源。当前大鱼吃小鱼的食物模型与贴图来自独立依赖包，已适配；通用自动依赖解析仍待完善。
- 基础运行验证应覆盖失败/结算/返回重开，并检查原版 UI 的实际可见状态。FairyGUI 组件创建成功不代表文字、按钮或控制器状态已经正确显示。截图应包含叠加 UI 的实际游戏区域。
- 已有的替代素材版本若要求改用原资源，应重新检查缓存并进入资源适配，不能继续由文本模型要求用户重复提供本机已有文件。

- 工具页面仅保留两类服务：微信小游戏转 Web 服务、AI 服务。显示实际在线、异常、未配置状态。
- 执行器随平台启动；AI 按配置调用，支持本机 Codex 备用。不能把未实际调用或未测试的状态标记为成功。
- Unity 玩法适配采用 Three.js 重写路径，明确原资源复用与逻辑重写范围，不声称完整恢复原版。
- 续作优先修改已入库版本，保留原资源、上下文、历次意见和版本；不得悄悄退回无原资源的简化游戏。

## 页面与入口

- 小游戏库第一、总览第二；总览顶部不再放工具服务和自动转换两个快捷按钮。
- 保留候选游戏、批次管理、任务中心、验收中心各自职责。批次是一组游戏，任务以单个游戏为单位。
- 登记、创建批次、实际启动转换是不同动作。现有“链接自动转换”会直接开始转换，不能描述成“仅登记”。单独登记可通过候选接口完成；独立的“仅登记”页面按钮尚需另行实现，不得在文案中声称已经存在。
- 批次名称、状态和详情按钮可点击；详情列出每个游戏的状态、原因和对应操作。

## 任务与批次

- 页面每 3 秒自动同步任务、批次、验收及看板状态，打开任务/批次/验收弹窗也持续更新；保留输入草稿、勾选项、焦点与滚动位置。后台标签恢复可见或网络恢复后立即同步，连接失败显示提示并自动重试；服务健康每 30 秒读取已有结果，不自动调用付费模型。
- 多轮沟通属于同一个游戏任务；对话、每轮结果和版本历史可追溯。
- 续作通过浏览器运行验证但仍有基础还原缺项时，自动保存不可变草稿版本及截图，任务保留缺项原因，不进入待验收；不得因缺项丢弃本轮已验证的修复。下一轮继续使用最新草稿与原资源来源记录。
- 处理中、待回复、待验收、已完成、异常含义独立。缺信息不应变成技术失败。
- 有已验证草稿但基础还原缺项时显示“待完善”，不计入执行异常；已有已验证草稿时，后续一轮失败不能覆盖整体进度：主状态仍为“待完善”，单独显示“上次续作失败”和错误原因；无可试玩草稿时才以“执行失败”为主状态。执行失败计数保留，不能隐藏真实错误。候选状态同步当前任务，批次暂停状态保持独立，不因有草稿而显示成功。重试使用明确的继续修复要求，不能将上一轮的结果说明或错误文本冒充用户修改指令。
- AI 提问时释放租约，用户回复后续作。退回修复自动形成下一轮。
- 缺少用户才能补充的对照信息时，通过任务对话转为待回复，保留当前草稿与缺项清单；不能只在外部聊天要求提供资料。管理员可通过 `jobs/{id}/request-input` 为未执行的阻断任务补录具体问题。用户在原任务发送回复后沿用现有版本继续，不能伪造用户回复或为了改状态重跑任务。当前页面支持文字回复，录屏附件上传及自动分析尚未实现，不得声称已经支持。
- 新版替代旧版后，旧任务不得继续污染异常和待验收数量。
- 批次支持开始、暂停调度、恢复、停止、继续未完成任务、仅重试异常任务。
- 暂停不领取新任务；停止撤销运行租约并结束本地任务进程。已经发出的远端推理请求是否停止计费取决于提供方，不能保证撤销远端请求。
- 重试不得重跑已完成、待回复或待验收的游戏。恢复不得覆盖另一个活动任务。

## 验收与截图

- 待验收与已验收分区；已验收显示结果、时间，不能仍显示“开始验收”。
- 功能验收只确认玩法和画面；资源使用信息原样保留，发布单独检查。不能自动伪造使用授权。
- 验收弹窗只展示产出截图，不展示重复的来源截图区域。
- 详情页优先使用当前版本的实机截图，图片缺失时明确说明，不用封面插画冒充实机图。
- 待验收卡片、已验收卡片、验收弹窗统一按比例铺满显示，允许裁切，不拉伸。
- 自动截图优先抓取最大的可见游戏 canvas，避免把承载页面的侧边背景拍进截图；没有符合条件的 canvas 时保留页面截图。
- 对含侧边背景的导入截图，报告可提供 `preview.zoom`（1–8），服务端保存到版本 `preview`。前端只读版本元数据，不按游戏 ID、名称或文件路径写特殊裁切规则。
- 默认 `preview={fit:cover,zoom:1,position:center}`；本地导入和自动转换共用同一验证函数。
- 原始截图和运行包保持可追溯。现有寿司与 Frost Land 的显示参数通过一次性迁移保存到版本数据，不改变原图。
- 图片验收必须打开列表、详情、验收弹窗检查实际画面；只验证 HTTP 200 或 CSS object-fit 不足以确认无留白。

## 游戏名称

- 游戏详情支持重命名，“编辑资料”可修改名称，名称为 1–120 个字符。
- 名称同步到游戏库、候选列表、任务、批次内游戏、验收、版本展示与试玩入口。
- 批次名称独立，不随游戏改名被强行替换。
- 手工名称优先，自动采集不能覆盖。历史代码快照与文件目录不因改名被移动。

## 验证要求

- 状态与接口：`tests/test_conversations.py`、`test_batch_controls.py`、`test_game_rename.py`、`test_local_intake.py`。
- 验收真实按钮：`tests/test_acceptance_ui.py`，验证通过后移入已验收区。
- 截图元数据：`tests/test_presentation.py`；图片视觉检查以截图内容为准。
- 现有成果使用只读检查；新状态流转和实际 AI 试验使用隔离数据库，不替用户验收真实游戏。
- 新需求应更新本文件及对应代码和必要测试；尚未实现的能力必须明确列出。

### 游戏模板的交付定义

- “带说明的游戏模板”指每一个移植后的游戏工程及该游戏的说明文档，不指抽象的通用模板或模板生成器。
- 每个游戏应随版本交付说明文档，涵盖游戏简介、玩法与操作、运行方式、工程与资源说明、测试结果及已知限制；未验证内容不得描述为已实现。
- 当前自动补写的基础 README 只有运行入口、来源等信息，不代表完整游戏说明已自动生成。

### 流程展示中的代码包获取

- 第 2 步为获取游戏代码包：通过反编译提取，或用户协助在 PC 微信运行目标小程序并加载游戏后，由服务定位匹配缓存包（wxapkg）与下载资源，再解包分析。不能以普通链接页面采集替代该步骤的说明或证据。
- 用户协助运行应明确标注；获取缓存包不等于已恢复完整源码。第 3 步继续使用获取的材料进行反编译分析、适配或 AI 复刻。

### 单游戏原版优先闭环（当前优先目标）

- 主目标是用户输入 HTTP(S) 游戏链接或微信小程序分享链接，获取目标游戏代码包、运行包及依赖资源，优先原版运行，再做浏览器适配与对照测试。先完成单游戏链路，再扩大外部搜集规模。
- 有可用代码直接复用代码，有可用运行包优先复用运行包；不能因完成静态分析就无条件进入 AI 重写。AI 优先用于接口和资源适配、定位错误与修复。
- 缓存不足时允许用户在 PC 微信打开目标游戏；目标行为是检测匹配缓存后继续原任务，不要求用户手工导出资源。分享口令解析、匹配缓存监测和自动续接尚待接入。
- 解包必须保留包内所有文件类型、原始相对路径及哈希，不能只提取图片音频，也不能打散目录。当前解包器已实现该要求，在容量限制内提取所有包成员；超限或非法路径明确失败，不输出完整性成功清单。
- 引擎插件可能具有独立 AppID，必须依据配置识别依赖，不能用游戏 AppID 解密其他插件包。已在回转寿司的已知三个包上验证 1087 个成员全部提取；插件自动发现、下载缓存依赖闭合仍未完成。
- 包内成员提取完整不等于全部运行资源齐全。需追踪分包、插件、远端依赖、图集、模型、贴图、动画、字体、音效和 UI，并记录无法获取或适配的部分。
- 交付目标为原版基础玩法、场景、角色、动作与 UI 的一比一网页还原；只有浏览器启动成功不能判定一比一。必须保留原版对照依据、实际动作测试和差异清单。未解决差异保留待完善版本，不能交付简化游戏并标完成。
- 当前内置自动分支仍存在静态分析后转 AI 重建的路径；原版优先路由、浏览器运行适配、依赖完整性检查及原版对照验证尚未全部实现，不得称本次解包修复已完成整个闭环。

### 依赖清单与原版优先（2026-10-20）

- 游戏依赖清单覆盖代码与引擎、资源、配置数据、后端服务、平台接口。逐项记录待分析、已取得、待获取、待重建/适配、已验证或不适用，以及证据、原因和下一步。已取得不等于已验证。
- 执行器按解包清单生成保守清单；本地静态扫描支持哈希校验、缓存文件检查和接口引用线索。扫描覆盖范围必须明确，不能将清单生成等同于依赖完整识别。
- 管理端与带有效任务租约的执行器共用依赖更新接口，使用 revision 防止覆盖，历史单独保留。任务中心展示清单并随现有轮询更新。
- 新产物带有已登记依赖清单时，未闭合依赖阻止进入待验收；运行成功仍可保存草稿。验收接口同样检查版本快照和当前清单。旧版本不被追溯修改；没有清单的历史流程仍兼容，不能据此认为历史产物通过新要求。
- 取得原版 JS/WASM 后，内置自动路径不再无条件转 AI 重写：保留材料、分析并明确适配阻断。通用原版运行适配、自动依赖下载与后端重建尚未实现；外部转换服务仍可按原接口执行。
- 后端缺失不必长期等待用户提供原版服务器。可以建立重建计划，由管理端将未执行任务转为“依赖待处理”，清除已失效的问题，不伪造用户回复、不启动无效重试、不自动验收。

### 任务推进与缓存续接（2026-10-20）
- 微信分享链接已有候选 AppID 时，默认读取该 AppID 最新缓存包，完整解包；未知身份仍需确认，不按最近缓存猜测。
- 同时保存该游戏 cacheList 中的下载资源，记录 URL、文件名、大小和哈希；限制在对应游戏的资源缓存目录，缺失、拒绝和超限不得冒充完整获取。当前支持 Cocos cacheList，其他缓存格式仍需适配。
- 原版运行适配、后端重建和资源引用闭合，不能由缓存索引全部保存替代。
- 管理端可向原任务追加实际工作记录，不伪造用户回复，不触发重试或改变验收状态。

### 原版配置发现与浏览器接口（2026-10-20）
- 从原版 JavaScript 批量赋值推导配置字段，按原代码实际读取的右侧字段（包括别名）匹配该游戏 temp JSON；只保存引用到的对象/数组表。玩家账号存储、登录令牌不作为配置来源。
- 配置清单列出源哈希、派生文件哈希、字段匹配和缺项；静态匹配不代表版本兼容或基础玩法已经验证。
- 共享浏览器适配层提供窗口尺寸和可见性事件；无本地登录实现时明确记录依赖阻断，不伪造 SDK 登录成功。
- 几何王国已验证原版加载场景启动；主场景、战斗、后端和完整资源闭合尚未完成。

### 代码复用与二次开发：长期工作标准（2026-10-20）

- 用户对“源码”的实用判断标准是：能否二次修改和使用，能否将代码或模块移植到其他游戏。后续所有游戏复刻、原版适配、续作与交付都应考虑这一目标，不以恢复原作者目录、语言或编辑器工程为唯一成功标准。
- 分别评估“能在当前游戏里修改”和“能抽取到其他游戏复用”，前者成立不代表后者已验证。发布后的 JS 也可能具有复用价值，不能仅因没有原始 TS 工程就判定没有可用代码。
- 交付说明应列出可修改的逻辑、可提取和移植的模块、引擎/资源/平台/后端依赖，以及实际验证步骤和未验证部分。区分“已验证可二次开发与移植”“可修改但移植需拆解适配”“主要可运行、核心逻辑复用受限”；无移植验证时不得声称已经可跨游戏复用。
- 只有 Unity WebGL/WASM 等运行产物时，不能以可启动或可替换资源推定核心逻辑可修改、可移植。模型、贴图和动画的复用属于资源复用，与代码复用分别记录。
- 我们重写的代码可作为二次开发成果，仍须准确标注来源，不称为恢复的原版逻辑。原始工程、发布代码、重写代码的来源与使用许可独立记录，不与技术上的可修改性混同。
- 本条确立长期工作与交付评估要求；本次仅更新约定，尚未新增自动复用能力检测、结构化报告校验或跨游戏移植验证，也不追溯认定历史版本已满足要求。
