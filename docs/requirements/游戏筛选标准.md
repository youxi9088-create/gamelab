# 游戏筛选标准

> 版本 v0.4 ｜ 2026-11-04 ｜ 状态：待评审
> 用途：找游戏、生成游戏、推荐游戏时，判断"一个游戏是否达到**准入门槛**"。

---

## 一、这份标准是什么

一句话：定义游戏的「**准入门槛**」——**达到门槛才准入，低于门槛就筛掉。**

- 共三条门槛，低于任何一条就筛掉（一票否决）。
- 边界：这份标准只判"游戏本身"，不含工程实现问题（加载慢、卡顿、货不对板、适配 bug 等）——那些走工程验收，不在这里。

---

## 二、准入门槛（三条）

### 门槛一：玩法非简单换皮

- **门槛**：同一玩法/类型**已有版本**时，新版本必须在交互形式、UI 布局或玩法实质上有所改变。
- **低于门槛的情形**：仅更换数值或美术资源（皮肤/素材），交互、UI、玩法实质都不变，与既有版本体验相同。
- **案例说明**：
  - ✅ 低于门槛：已有「消消乐」，新的只是把"水果"换"宝石"、得分 100 改 200，消除规则、布局、操作不变 → 筛掉。
  - ⭕ 达标：换了美术、还改了核心机制（三消→点击合成）或新增了玩法层（关卡/技能/收集）。

### 门槛二：游戏完整度达标（撑得起累计游玩约 10 分钟）

- **门槛**：能支撑用户**累计游玩满约 10 分钟**——单局或反复重玩，用户能持续玩下去，而不是很快"玩到头"。
- **关键口径**（避免误杀 Flappy Bird 这类游戏）：
  1. 看「累计游玩时长」，不看「单局时长」——单局几秒没关系，能靠重玩累计玩满 10 分钟就达标；
  2. 看「实际能玩多久」，不看「内容/关卡有多少」——内容再少、有强重玩驱动也达标；
  3. 重玩循环计入时长——"再来一局冲更高分"是实打实的游玩时间。
- **案例说明**：
  - ✅ 低于门槛：点几下就通关，全程一两分钟，通关后没有任何"再来一局/继续玩"的理由 → 无论怎么玩都凑不满 10 分钟 → 筛掉。
  - ⭕ 达标：Flappy Bird 单局几秒，但"差一点就过"让人一局接一局、累计能玩很久（跳一跳、羊了个羊同理）。

### 门槛三：具备「目标 → 玩法 → 反馈」基础闭环

- **门槛**：具备基础闭环——**明确目标 → 通过规则/玩法达成目标 → 达成后实时反馈 → 给出新目标**，让用户有继续玩下去的理由和动力。
- **低于门槛的三种情形**：
  - ① 没有目标（只有简单交互互动）；
  - ② 有目标但没后续（达成后戛然而止、太短）；
  - ③ 有目标但反馈不够（达成后不产生继续玩的意愿和动力——挑战欲、成长感、成就感）。
- **案例说明**：
  - ✅ ① 模拟器式游戏，只有"点一下、动一下"，没有要达成的目标 → 筛掉。
  - ✅ ② "点三下合成一个东西"就结束，达成了目标但没有下一步 → 筛掉。
  - ✅ ③ 切水果切完只显示"游戏结束"，没有分数、排行、"再挑战"，用户切完没动力继续 → 筛掉。
  - ⭕ 达标：切水果有分数、连击、排行榜、"差一点破纪录"，用户会为更高分再来一局 → 闭环成立。

---

## 三、生成质检环节（不是门槛）

「可玩通」不是准入门槛，而是**生成流程的前置质检环节**：

- 游戏生成后 → AI 检查 bug/数值 + 试玩验证 → 修复 → 确保游戏可玩通；
- 可玩通之后，才进入上面的三条门槛判断。
- **为什么不是门槛**：可玩通是"可修复的状态缺陷"（bug、数值崩坏，AI 修好即可）；而门槛是"不可修的本质属性"（换皮、内容少、没闭环，修 = 重做）。
- **修复成本**：若 bug 多到修不动，可设修复轮次上限（修 N 轮还不过就放弃），属运营细节，不是一票否决。

## 四、移出准入门槛的项（备忘）

之前讨论过、但最终**不算门槛**的项，归宿如下：

| 项 | 归宿 |
| --- | --- |
| 学不会（规则复杂/要教程） | 游戏设计体验问题，不在准入标准里 |
| 拖太长（单局十几分钟） | 转为优先推荐考量，按用户类型匹配（有人就喜欢策略长局） |
| 没目标/没追求（宽泛主观） | 已收敛为门槛三的客观三情形 |
| 横屏/双手 | 游戏机制决定的正常设计，不否决 |
| 外设依赖 / 合规 | 生成和输出环节自动适配/屏蔽，不进准入判断 |
| 可玩通（无死锁/数值崩坏） | 已移出为「生成质检环节」（见第三章），不是门槛 |
