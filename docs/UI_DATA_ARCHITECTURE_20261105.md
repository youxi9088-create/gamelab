# 界面数据读取重设计（2026-11-05）

## 触发问题与口径

验收写入成功后，列表重新读取了耗时统计快照，可能继续展示旧卡片。实测旧快照年龄约130秒，历史大JSON解析栈也被远端日志捕获。不能将“数据更新延迟”解释成验收失败或用户网络断开。

## 已实施的路径

records仍是业务权威记录，原始报告和历史版本保留。新增ui_live_records保存候选、任务、版本、批次、来源及主配置的轻量列表字段，排除报告、原始采集、源码、租约令牌等大字段。SQLite触发器在原写事务中维护此表：业务提交与列表状态一起提交，业务回滚时列表也回滚，删除同步删除。旧数据一次回填，新库初始化自动创建。

UI快照子进程分开运行统计计算与实时发布。统计沿用原始证据和计算逻辑，保留ui_statistics_built_at；发布循环每2秒读取轻量表，合并已有展示元数据，替换任务、版本等实时列表，并计算实时排队数量与待验收版本数。浏览器原有10秒轮询继续使用原接口，无需云静态镜像变更。实际可见延迟由读取时间与两级轮询共同决定，不承诺零延迟。

验收中心按最新version.status筛选，已通过版本不等待费用或历史统计重算即可离开待验收。新版本和删除记录来自当前轻量表，不依赖旧快照中是否存在该ID。旧快照中的展示信息只作为补充，不覆盖最新状态。完整规格、源码依据及玩法报告继续通过单游戏详情接口按需读取。

## 验证

远端1087条轻量记录约1.1MB，三次读取0.422、0.266、0.328秒。隔离回归验证了陈旧review被已提交approved替换、原快照不修改、报告不进入轻量表、回滚不会产生假验收。来源管理相邻回归另行记录在运维回执。仅重载UI快照子进程，UI父进程保留旧快照等待预热，没有重启或中断转换任务。

测试站真实登录后读回ui_live=true、ui_snapshot_age_seconds=1.7，统计时间独立保留。该结果证明新协议上线，不表示所有页面统计已实时化或游戏已自动通过验收。

## 保留的边界

费用、历史用量、引擎与分类证据分析、供货详细分析仍由后台统计更新；这些计算的算法与历史依据不改写。当前实时通道重点覆盖验收与转换调度列表，供货详细状态尚未迁入该轻量表。冷启动仍须取得首份基础快照；后续应将统计计算独立进程化、增加持久化基础快照及页面分区更新时间提示，并按实际负载测试验证延迟目标。不能把这次改动宣称为全部数据架构工作结束。

若需回滚，可停止使用新UI发布器并恢复原子进程代码；原业务记录未改结构，轻量表与触发器可单独移除。不得通过回滚覆盖业务期间新增的验收、任务或游戏版本。
