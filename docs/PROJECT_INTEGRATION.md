# 其他项目接入转换服务

版本：1.0 · 2026-10-23。先读 [服务规范](CONVERSION_SERVICE_STANDARD.md) 和 [适配范围](ENGINE_PLAYBOOKS.md)。

## 1. 先选择交付目标

接入前提供：来源 URL 或可用包、目标浏览器及设备、希望保留的玩法、是否要求离线、需要修改的规则、是否需要提取模块、允许缺少的在线功能。

这些是接入评审材料，不是当前 `/api/conversions` 全部可接收的字段。现有链接接口提交后，可通过任务沟通记录补充目标；尚不能在程序上按结构化目标筛选适配器。

| 目标 | 选择和验收重点 |
|---|---|
| 让原玩法在另一个页面运行 | 运行包、宿主、尺寸输入、离线依赖、代表性玩法 |
| 修改规则和流程 | 先确认业务逻辑可编辑；运行包通过不能代替源码目标 |
| 提取模块组装新玩法 | 先确认模块边界、依赖和独立夹具；未验证提取能力须单独适配 |

## 2. 当前可用接入方式

### A. 同一部署、共享数据的项目协作

管理员分配账号，操作员提交／处理任务，只读用户查看。当前权限是项目内共享数据，不提供多个项目间的数据隔离。

当前门户 API 可用于受控集成验证：

1. `POST /api/auth/login` 建立会话；凭据保存在接入方服务端，不写入网页代码或 Git。
2. `GET /api/session` 获取 CSRF。管理写请求发送会话 Cookie、`X-CSRF-Token`，遵守配置的 Origin 检查。
3. `POST /api/conversions` 提交 `{"url":"https://example.com/owned-game"}`；多链接使用 `{"urls":["https://example.com/owned-game"]}`，保留返回的任务／批次标识。单链接和多链接返回形状不同，以 [API](API.md) 及实际响应为准。
4. `GET /api/state` 按任务 ID 查任务及版本，低频轮询并在异常时退避。当前是全站状态接口，不是项目隔离的任务查询 API。
5. 存在缺项时查看 `pipeline.presentation`、阶段记录和版本报告；自动接续期间不重复提交。明确阻断后按原因补材料或使用任务沟通／重试接口。
6. `review` 时人工试玩验收；`completed` 表示任务已验收。按版本读取说明书和产物：`GET /api/versions/{id}/specification.md`、`GET /api/versions/{id}/download`，均需管理会话。
7. 发布及下游供货单独处理，不能仅凭下载成功自动发布。

以上是现有门户会话协议，尚不是面向第三方应用的稳定服务账号协议。浏览器跨站调用不能通过关闭 CSRF 或放宽 Origin 来解决；正式跨项目接入须建设专用项目调用协议。

### B. 接入外部采集或转换执行器

已有 `/api/v1/*` 工具接口使用独立 Bearer 凭证，支持候选提交、领取、心跳、事件、产物、完成及租约校验，详见 [API](API.md)。

**工具是任务执行方，不是转换服务消费方。** 工具令牌不能调用 `/api/conversions` 或任意管理查询；外部项目不要通过领取全站任务来模拟“查询自己提交的转换”。工具重试可使用其已实现的幂等协议，不能推定所有管理 POST 都有相同幂等保证。

### C. 获取已验收游戏供另一个系统使用

使用不可变版本下载，或已有独立 [供货流程](SUPPLY_INTEGRATION.md)。同时交付规格、修改范围、依赖和验证边界。供货签名下载与普通门户下载是不同协议，不能混用认证或地址。

## 3. 最短接入验证路线

1. 按手册选一种已支持的运行契约，用自有小型夹具走通鉴权、提交、排队、查询和取回产物。
2. 验证重复请求、超时、阻断、重试、版本更新及凭据失效的处理；测试数据库与正式库分开。
3. 核对取回版本与报告一致，检查入口、运行环境、实际目标玩法及约定的修改点。
4. 验证接入方不会把草稿／待验收当完成，不会把历史阶段成功当本轮新验证。
5. 完成项目凭证、权限范围和交付协议后，再接生产任务；真实游戏执行作为明确授权的实际交付。

## 4. 必须避免的接入误区

| 误区 | 正确处理 |
|---|---|
| 支持同一引擎，就一定支持同一网站所有游戏 | 按引擎、包格式、宿主和实际材料逐项预检 |
| 调用超时就重新创建转换 | 保留任务 ID、查询现有任务，再决定是否重试 |
| 等待模型时反复点“继续” | 先读当前状态；队列与执行中的任务不能并发续作 |
| 有画布或 ZIP 就算交付完成 | 检查玩法证据、版本状态和目标能力 |
| 本地路径或 127.0.0.1 可直接给另一个项目 | 使用部署的公网入口及平台返回的相对路由；不暴露服务器路径 |
| 旧轮次成功可覆盖新版本问题 | 每次取明确版本，验证证据绑定基线 |
| 共用一把管理员密码作为项目 API 密钥 | 正式接入补项目级凭证及最小作用域 |
| 选择本地 Codex，生产就能完全脱离该机器 | 核对桥接进程实际部署位置及上游登录；依赖开发电脑时应迁移桥接或配置可用 API |

## 5. 正式项目 API 的待实现契约

以下是后续开发要求，没有给出可调用的新 URL，避免接入方误用：

- 版本化能力列表及预检：输入条件、支持级别、缺项、预计采用的适配器及规则版本。
- 项目鉴权及作用域：提交、读取、续作、取产物分别授权；先明确共享数据还是隔离部署。
- 转换请求：项目请求 ID、来源、交付目标、基线版本；提交具有明确的幂等键与冲突语义。
- 查询：按任务返回阶段、结果、问题、下一动作、最新版本；支持分页事件和退避提示。
- 交付：可校验的统一清单、下载授权、哈希、规格、二次开发能力和验证覆盖。
- 故障：稳定错误代码、是否可自动重试、原失败节点、保留产物及恢复条件。
- 可选通知：服务端签名、重投去重、补查接口；回调失败不改变转换事实。

在这些接口上线并通过隔离契约测试前，对外说明为“已有共享转换核心，可进行受控接入；正式跨项目 API 待补齐”。
