# 下游供货要求与当前缺口

整理日期：2026-11-03。依据为 template-supply-client 1.0.1、[10-30批次供货评估报告](https://skillstores.new.ndhy.com/reports/8na9lgynwx)及本线程远端供货回执。

本文是盘点，不表示新一轮修复、验收或提交。11月1日报告是历史评估；实时状态必须通过原submission_id查询。评估报告中的384KB是当前下游制作能力提示，不是API接包的统一体积硬门槛。

## 一、下游实际要的交付

下游需要能在无外网、无既有Cookie的环境中运行，并可进一步修改、换题材、生成新游戏的静态Web包。完成抓取、能在我方试玩、下游受理、生成模板、上架试跑通过，是五个不同阶段。

| 要求 | 我方现状 | 尚缺与应进入的流程 |
|---|---|---|
| 请求鉴权、指纹、时间戳、新nonce、原始字节签名 | 已有协议自检与真实接收记录 | 服务账号读取配置的权限曾漏配；已修配置ACL及错误分类，原常驻进程尚待安全重载 |
| ZIP为标准包，根index.html，可直接静态运行 | 已有独立交付副本及根入口整理 | 交付副本本身的无网运行与操作验证尚未成为每包自动闭环，不能只继承整理前证据 |
| ZIP≤100MB、解压≤500MB、≤2000文件，无越界路径、链接、非Web执行文件和密钥 | 已有本地检查、无损压缩比处理 | 老安全问题有下游误判已修历史，必须先同步，不能盲目重做；剩余个案按真实包复核 |
| HTTPS白名单可下载，URL有效期覆盖接收，完整ZIP SHA256一致 | CS上传与真实回下载校验已验证，44条已有接收记录 | 原网络/配置失败需沿原提交恢复；不得把上传成功算模板生成 |
| 脚本、模块、模型、JSON、字体、图片、音频全部随包，入口和源码不能残留必需外联 | 已有静态审计及离线验证能力 | 仍有缺资源包；CSS字体补齐原来被重命名分支跳过，已修共享代码；实际交付副本还需复验 |
| 接受静态Web产物，不接受需构建工程及协议不支持的二进制运行时 | 已能识别和阻断 | 当前2条TOOLCHAIN_UNSUPPORTED，不能只改文件名或扩展名放行；先分流到支持的交付路线 |
| 可分发声明和权利人，来源、许可可追溯 | 用户指定gcy默认政策已登记，27条缺声明已补齐 | gcy是用户声明，不是新增第三方授权文件；第三方代码和素材的许可依据仍须保留与核对 |
| 可重放的真实玩法验收路径 | 有实际动作、截图及部分协议动作转换 | 坐标/持续按键/刷新不能全部无损转换；需要稳定入口选择器、画布相对坐标证据、明确玩法反馈，在整理后的包中重放 |
| 可修改逻辑、参数、文案和素材 | 部分包具备，部分仅可运行 | 大HTML/JS单体、引擎库与业务混杂仍多；需按职责拆分、vendor独立、配置和文案集中，不能机械按行切文件 |
| 换皮后确实加载替换素材，核心玩法不坏 | 原游戏试玩不覆盖这项 | 缺少我方自动换一份素材/一组配置/一组文案后真实试玩的验收环节；截图不能当作可替换游戏素材 |
| 原目标、原提交幂等跟踪，终态停轮询，改包用新版本新提交 | 已有共享队列与校验 | 要保证运行进程实际加载新代码；平台侧失败只查询，不当作供应方资源缺失盲重推 |

## 三、已确认的具体缺口

- PolyRace：GLTFLoader注释中的assets/models/model.gltf被当作真实依赖。新检查已排除注释并复验通过，原供货记录已恢复；不是下载假模型解决。
- Sir Rolls-A-Lot：先有同类注释误报，复验又暴露assets/目录前缀被当文件。共享审计已排除纯前缀提示，仍须新的实际包复验才能认定解除。
- Jose’s Kingdom：main.js引用no-booster-probe.js、level-generator.js及多份图片音频仍被列为缺失。需核对原源码用途及真实请求，补抓实际必需文件；不能统一忽略。
- Don’t Trust the Game：index.html仍引用%23n。需查它是误采集/错误改写还是实际资源，不按看起来像锚点直接放行。
- Jade Idol Temple：历史下游报告为three.js脚本404；原目录有Three文件不证明已交付ZIP路径正确。还需下载实际提交包，核对整理后的引用与文件，并重放。
- 霜原炉火：下游自动操作未证明进入玩法，报告标有平台侧误判因素。需要明确acceptance_steps及实际状态反馈，不能只用“我方能打开”反驳下游证据。
- Frost Land等两条不支持包：当前协议不接受对应运行时，应分流，不伪装为可编辑HTML模板。
- 历史几何王国、寿司、跑酷的安全/密钥问题曾被下游确认存在误判；不要继续引用旧问题当当前事实。最新needs_your_fix五条须取新revision问题清单后再定根因。

## 四、流程补齐顺序

1. 运行环境：确认实际服务身份能读配置，新共享代码完成安全重载。临时独立供货进程曾因SSH结束退出，不能作为已持续生效的证据。
2. 转换交付：引擎及协议能力分流，依赖清单真实闭合；源码、运行包、供应副本分别保留哈希，不覆盖已验收产物。
3. 验收前：对最终供货副本执行无网启动、必需请求检查、真实操作路径及反馈验证，输出与该ZIP摘要绑定的报告。
4. 可改造性：业务按职责拆模块，vendor独立，参数/文案集中；对可替换素材、参数和文案做受控替换与玩法回归。
5. 正式供货：gcy用户声明与原来源许可一并随包，上传回下载校验，稳定提交编号和不可变载荷。
6. 下游跟踪：问题按配置、包、玩法路径、可改造性、平台侧分类，并将可修问题反馈到转换检查，而不是仅在供货列表显示失败。

优先级最高的是：共享代码实际生效、交付副本运行与玩法验证、真实缺资源闭合。单纯继续补字段或重复上传不能覆盖这三项。
