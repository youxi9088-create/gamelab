# 引擎与运行契约适配流程手册

版本：1.0 · 2026-10-23。与 [服务规范](CONVERSION_SERVICE_STANDARD.md) 配套。

本表为代码核对后的能力范围，不是所有同引擎游戏的成功率承诺。案例不作为识别条件；通用探测路径不等于完整引擎适配器。

## 1. 路径选择表

| 运行契约 | 输入证据／前置条件 | 专用处理顺序 | 交付与边界 | 实现入口 |
|---|---|---|---|---|
| Cocos 2 Web | `_CCSettings`、`cocos2d-js`，或已登记 Web 配置及匹配材料 | 入口识别 → 资源及已声明包采集 → 本地引用／已知宿主适配 → 场景和玩法验证 | 保留发布包；业务脚本可编辑程度逐包确认，不能保证恢复 Creator 工程 | `executors/discovered-web.cjs`、`web_runtime.py`、`web-profiles/` |
| Ruffle／SWF | 入口明确声明 Ruffle 和可提取 SWF | 获取 SWF 与播放器 → 独立宿主 → 禁外网启动 → 实际输入和闭环验证 | SWF 核心为运行包；播放器宿主可编辑；不保证还原 ActionScript 工程 | `executors/discovered-web.cjs` |
| Defold HTML5／WASM | AI 方案绑定入口哈希，入口有 `dmloader.js` 与 `EngineLoader.load(` | 校验方案 → 获取引擎／归档／WASM → 适配已声明宿主 → 运行及存档验证 | 保留原运行包；页面／宿主可编辑；Lua 工程及核心模块提取未恢复 | `executors/repair_context.py`、`discovered-web.cjs` |
| Remix Three | 明确的 Remix 宿主与 importmap 模块入口 | 解析模块依赖 → 获取明确媒体资源 → 替换本地宿主 → 真实玩法验证 | 保留 JS 逻辑；独立模块仍需拆解；不提供原站在线账户、购买及排行 | `executors/modular_web.py`、`adapters/remix-local.js` |
| HTML5 通用浏览器探测 | 实际公开脚本入口、方案及源哈希匹配 | 捕获实际请求 → 保存原包 → 隔离启动 → 检查实际玩法和依赖 | 探测路径；画布出现仅是启动证据；动态资源、构建工程及私有后端不保证闭合 | `executors/discovered-web.cjs`、`auto_repair.py` |
| 内嵌 HTML/lib | 已有内嵌 HTML、明确资源映射和已知宿主接口 | 提取 → REA 分析 → 显式资源映射 → 宿主适配 → 实际检查 | 已声明契约范围内适配；未知宿主方法或外部代码保留阻断 | `executors/web_embedded.py`、`embedded_runtime.py` |
| Cocos 3.5.1 微信原包 | 明文／V1MMWX／支持的 define 包装，主包、分包及匹配插件可取得 | 校验材料 → 独立原包服务 → 转换静态包 → 平台运行及交付检查 | 指定原包路径；`built_unverified` 不是验收；不能用 Web 链接猜测 AppID 材料 | `executors/package_converter.py`、`services/wechat-web-service/` |
| 已有静态源码／本地包 | 可信目录或受校验 ZIP，明确入口 | 快照 → 分析依赖 → 浏览器检查 → 版本与交付检查 | 不属于新增引擎适配；可维护性按实际源码说明 | `executors/worker.py`、`tools/import_local_review.py` |

Unity、Godot、Laya 等尚无通用转换承诺。已有资源提取工具、人工导入游戏或某个专项案例不能提升为通用支持。

## 2. 宿主适配与引擎适配分别登记

引擎负责运行游戏；宿主可能负责广告、账户、存档、支付、排行榜或窗口尺寸。它们须分别检查。

- Poki：仅当入口明确声明 SDK 并支持初始化失败分支时，选择 `poki-offline`；广告和广告奖励不可用。实现：`executors/adapters/poki-offline.js`。
- Remix：按已有模块契约提供本地宿主，不伪造线上服务。实现：`executors/adapters/remix-local.js`。
- 游戏展示尺寸：登记到版本元数据，由共享尺寸适配处理；禁止前端按游戏名修正。
- 其他 SDK：检查实际调用及离线影响；没有适配时明确缺口。不能因为同属 Poki 网站就套用同一方案。

## 3. 已有案例如何复用

### Monkey Mart：Defold 与 Poki 宿主

- 已积累：Defold 契约、Poki 本地宿主、实际输入观察、IndexedDB／WASM 存档取证及刷新恢复检查。
- 新输入先检查：入口特征、SDK 初始化分支、资源取得情况、实际在线依赖。
- 可直接复用的是平台适配与验证工具；游戏核心仍为运行包。不要把“猴子超市移植通过”写成“所有 Defold 游戏均可自动转换”或“Lua 源码已恢复”。
- 常见坑：点击太短可能未被游戏帧观察；存档哈希不变不能单独证明失败；先确认保存触发条件，再分别执行升级与刷新观察。
- 案例任务和最新验收状态以平台记录为准，本文不复制易过时的任务状态。

### Hyper Strike：Remix Three

- 已积累：模块引用解析、本地宿主、真实得分结算、重开及本地存档验证路径。
- 新输入先检查：importmap 与依赖是否匹配已有契约，媒体资源是否可取得，是否新增在线依赖。
- 常见坑：不能把注释和字符串当 import；源码读取不能吞掉同轮浏览器操作；有 JS 不等于模块已脱离原宿主。

## 4. 适配器登记模板

新增能力复制以下表格填写。此模板是评审和交付文档格式，尚不是平台自动读取的注册 API。

| 字段 | 必填内容 |
|---|---|
| 能力 ID／规则版本 | 稳定名称、支持范围变化说明、代码 Git 提交 |
| 引擎与格式 | 引擎版本、原包／发布包／源码、入口特征 |
| 前置材料 | 主包、分包、脚本、资源索引、必要授权输入 |
| 识别及排除条件 | 可复验特征、反例、冲突时如何处理 |
| 宿主依赖 | SDK、服务器、存档、广告、支付、在线能力 |
| 转换步骤 | 每步输入、输出、失败类型、可恢复位置 |
| 允许修改范围 | 原始材料保护、可修改宿主或应用文件 |
| 验证要求 | 启动、输入、代表性闭环、继续、适用存档与负面检查 |
| 二次开发能力 | 可修改逻辑、可移植模块、依赖、复用级别 |
| 资源限制 | 文件数、容量、执行时间、调用预算及配置来源 |
| 恢复策略 | 基线哈希、检查点、必要回放、禁止重试条件 |
| 证据 | 自有夹具、隔离测试、授权真实案例、未验证范围 |
| 故障经验 | 触发条件、实际原因、修复方法、适用范围、回归夹具 |

流程升级必须兼容旧版本读取，不能重写历史报告。新案例发现的问题先判断是引擎、宿主、材料还是玩法验证问题，再归入对应共享层。
